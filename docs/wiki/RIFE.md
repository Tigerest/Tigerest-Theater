# RIFE AI 补帧

RIFE 在原视频帧之间生成中间帧，提高运动画面的输出帧率。补帧默认关闭；它会增加计算负载，插帧画质和实时性能取决于素材、模型、硬件与其他画质处理。

## 先确认平台和片源

| 平台 | 组件 | 支持输入 |
| --- | --- | --- |
| Windows x64，受支持的 NVIDIA GPU | NVIDIA 1.0.0 可选扩展，TensorRT | 最高逐行 SDR 4K / 60 fps |
| Apple Silicon Mac | 包内模型与插件，Core ML / Metal | 最高逐行 SDR 1080p / 30 fps、恒定帧率 |
| iPad | 包内原生滤镜，Core ML / Metal | 1920×1080、BT.709 SDR（8 位或 10 位）、23–30 fps，固定两倍 |
| Android、Apple TV | 当前不提供 | 使用正常播放 |

以上是格式门槛，不是所有设备都能实时达到的性能承诺。Windows 不自动缩小推理分辨率或把 HDR 转为 SDR 来满足条件；Mac 和 iPad 的 HDR、4K、变帧率及色彩信息不完整的视频保持原帧播放。

Windows Intel／AMD 显卡可以使用基础播放，但不能使用这里的 NVIDIA 扩展。Mac 使用自己的内置方案，不安装 Windows ZIP。

## Windows 在线安装

1. 打开「Emby 设置 → Tigerest Theater 设置 → 视频」。
2. 找到「NVIDIA RIFE 扩展」，点击「下载扩展」。
3. 客户端自动选显卡适配包；无法确定或没有匹配小包时使用完整兼容包。
4. 等待下载、核验和安装。页面显示下载大小、状态和具体错误。
5. 看到「请完全退出并重启客户端」后退出程序，包括托盘，再重新启动。
6. 回到「视频」，开启「AI 补帧（RIFE）」，选择模型和目标帧率，然后重新打开视频。2.9.4 起不再需要选择 MPV 配置模式；mpv.conf 里与 RIFE 冲突的改帧率滤镜和 `interpolation=yes` 会在开启时自动暂停，关闭后恢复。

架构适配包约 724–1040 MiB，完整兼容包约 2 GiB。下载临时文件、展开内容和引擎缓存都占空间，建议准备 10 GB 以上可用空间。扩展已带所需模型与私有运行库，无需另装 SVP、Python 或 CUDA Toolkit。

下载来自 GitHub，先经下载加速镜像 gh-proxy.com，失败时依次换用 ghproxy.net 和 GitHub 原址；文件按客户端内置的 SHA-256 核验，镜像只负责传输。都不通时可用下面的离线导入；正在处理时按钮暂时禁用，可用「取消操作」停止。

## Windows 离线导入

1. 在能下载的设备上取得原始扩展 ZIP：显卡架构适配包见 [v2.3.3 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.3.3)；不确定时可选[完整 NVIDIA 1.0.0 包](https://github.com/Tigerest/Tigerest-Theater/releases/download/v2.2.0/Tigerest-RIFE-NVIDIA-1.0.0.zip)。
2. 把完整 ZIP 复制到这台电脑，不需要解压，也不需要放到程序目录。
3. 在「视频 → NVIDIA RIFE 扩展」点击「导入离线包」，选中 ZIP。
4. 等待校验和安装；完成后完全退出并重启。
5. 使用内置配置，开启补帧，重新打开视频。

扩展名形如 `Tigerest-RIFE-NVIDIA-sm89-1.0.0.zip`，完整包为 `Tigerest-RIFE-NVIDIA-1.0.0.zip`。它们与 `TigerestTheater-版本-x64.zip` 客户端便携包不同。

客户端检查哈希、清单、版本和运行库兼容性。自行修改或重新压缩的 ZIP 不会作为正式扩展接受。完整 1.0.0 包 SHA-256：

```text
f7a7958b119b94b374df916b39ef36e9ed34f6df15eac4fb40153d30b2aab694
```

适配包覆盖 sm75、sm80、sm86、sm89、sm90、sm100、sm120，普通用户优先让客户端自动选择。每个小包仍包含三种模型；更换显卡后可能需要匹配的新包或完整包。

## 选择模型与目标

Windows 提供 4.25 lite、4.25、4.25 heavy：

- lite 运算较轻，可从它和较低目标开始。
- 4.25 用于日常均衡比较。
- heavy 用于对比画质，计算负载更高。

「RIFE 目标帧率」接受 24–360 的整数，或 0 表示源帧率两倍。实际倍率在 1.5–15 倍之间，以 0.5 倍为一档，选择最接近目标的档位；等距离时取较低档。

| 片源 | 输入目标 | 实际倍率 | 输出约为 |
| --- | --- | --- | --- |
| 24 fps | 36 | 1.5× | 36 fps |
| 23.976 fps | 60 | 2.5× | 59.94 fps |
| 24 fps | 60 | 2.5× | 60 fps |
| 24 fps | 84 | 3.5× | 84 fps |
| 29.97 fps | 60 | 2× | 59.94 fps |

目标 60 不一定得到恰好 60，视频时长仍保持不变。24→120 每张原帧要生成 4 张新帧；24→240 要生成 9 张。高刷显示器不能替显卡完成这些推理。

修改模型或目标后重新打开视频。先确认低倍率持续流畅，再提高目标或画质，能更容易判断是哪项增加了负载。

## 第一次准备引擎

第一次使用某个模型和输入尺寸时需要准备引擎。Windows 播放会暂时暂停，画面显示阶段、估算进度和已用时间；这可能持续数分钟。

完成后开始当前视频，用户主动暂停时不会强制播放。以后可以复用通过校验的缓存。进度是估算值，不是固定剩余时间；更换模型、尺寸、显卡或运行环境可能需要重新准备。

首次安装或扩展发生变化时会进行完整核验。后续在支持变更日志的本地 NTFS 上可快速检查；网络盘、ReFS 或相关功能不可用时继续完整校验。

扩展由同一客户端的配置档共用，引擎缓存按配置保存。便携版更新要保留 `data`。移除扩展使用「移除扩展」，再完全退出并重启。

## Windows 的同步方式

2.9.5.1 起，Windows 开启补帧后：

- 全屏播放按设置里的音画同步方式（默认「显示器重采样」），弹幕每次屏幕刷新都移动。全屏偶尔也会被系统合成（例如有置顶的小窗口盖在视频上），显示器重采样这时可能接连掉帧；客户端发现持续错时后，把这一集改回音频时钟，不弹性能提示，下一集再试。
- 窗口播放用音频时钟，因为窗口由系统合成，显示器重采样在合成下会掉帧。音频时钟下播放内核把每一帧对准屏幕刷新提交，高刷新率屏幕上 3 次、5 次刷新的交替大幅减少；弹幕跟着每一帧画面移动。
- 暂停 5 秒以上再继续时，客户端先在当前位置重新准备画面再继续，期间显示缓冲，约 1–3 秒；实测恢复后不再落后、掉帧。

2.9.5 在全屏和窗口都用音频时钟，翻页也不对齐屏幕刷新。

## Mac 开启步骤

1. 使用当前 Apple Silicon 正式应用，保留完整应用包。
2. 在「MPV 画质与插件」确认使用大河内置配置。
3. 进入「视频」开启「AI 补帧（RIFE）」。
4. 重新打开符合条件的视频，查看当前视频状态。

Mac 输出两倍帧率，使用系统 Core ML / Metal。无需额外下载 Windows 扩展，也不需要自行装一套 Python 环境。

## iPad 开启步骤

1. 在客户端设置的「视频」中开启「AI 补帧（RIFE）」，默认关闭。
2. 重新打开符合条件的视频：1920×1080、BT.709 SDR（8 位或 10 位，例如 HEVC Main 10 编码的动画）、23–30 fps。输出固定为两倍帧率。
3. 其他规格的视频原帧播放，不需要手动关闭补帧。

调整播放速度时补帧暂停、直接输出原帧，回到 1 倍速后短暂稳定再恢复。所以在[一起看](https://github.com/Tigerest/Tigerest-Theater/wiki/Watch-Together)房间里开启补帧时，客户端不靠微调倍速对齐进度，偏差较大时直接跳转对齐，Windows 和 Mac 也是这样。

补帧的流畅度取决于片源、设备型号和温度。实测中 M5 iPad Pro 播放 8 位 1080p 动画、同时开启默认画质和弹幕，约 11 分钟没有记录到渲染或解码掉帧；2.9.3 起 10 位片源也走同样的 GPU 颜色转换，同一台 iPad 播放 10 位 1080p 动画约 14.5 分钟（包括温度升高的阶段）也没有掉帧。以前 10 位片源会在播放约 9 分钟后开始持续掉帧。这些结果不代表所有视频和设备都能全程流畅。

## 判断是否实时

桌面播放时按 `Ctrl+J` 显示统计；按 2 或 `Ctrl+Shift+J` 查看完整处理耗时页，按 6 查看排查说明。

优先观察播放稳定一段时间后，解码／输出丢帧是否继续增加，以及音画偏差是否持续扩大。启动、缓冲和跳转留下的累计丢帧数，不代表之后仍在掉帧。

持续性能不足时会显示提示，由用户决定降低目标、换 lite、降低画质或关闭补帧。当前行为不会仅因性能统计自动把目标降下来；不支持的格式、倍速或真正的引擎／推理故障另有状态说明。

GPU 总占用率和单个渲染耗时都不能独自代表完整链路是否实时。解码、推理、shader、字幕和系统呈现共同影响结果。弹幕高刷也不要求视频补到相同帧率。

以往 RTX 4090 的部分 1080p 低倍率测试通过，不等于所有 GPU、4K、高倍率或全部模型均经实机验证。1080p→240、原生 4K60→120 等高负载用途不作普遍实时保证。

## 常见状态

| 状态或现象 | 操作 |
| --- | --- |
| 扩展已装但组件不可用 | 完全退出托盘和客户端后重启 |
| 已开启但本片没补帧 | 查看当前状态，核对格式和播放速度 |
| 正在准备引擎 | 等待当前阶段，留意错误提示和磁盘空间 |
| 持续丢帧或音画偏差 | 降低目标、换 lite、减轻画质负载再比较 |
| ZIP 校验失败 | 重新下载原始扩展包并核验摘要 |
| 更新客户端后提示不兼容 | 使用完整正式包，核对客户端和扩展版本 |

反馈时写明显卡／芯片、模型、目标、视频分辨率与帧率、SDR/HDR、当前状态和稳定播放阶段的统计，见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
