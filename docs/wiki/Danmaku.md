# 弹幕匹配、来源与纠正

弹幕和视频来自不同服务。视频使用你的 Emby，弹幕来自设置中的弹幕服务和手动添加的来源。新配置默认启用弹幕；以前明确关闭过的开关会保留。

## 自动加载的顺序

1. 开始播放时查询作品、季、集的共享匹配。
2. 命中后加载返回的弹幕；桌面沿用普通匹配的三行提示，在第一行作品和集名末尾加上「（共享）」，下方保留弹幕数量与手动纠正说明。
3. 没有共享结果或服务暂不可用时，继续自动识别或手动搜索。
4. 自动识别先确认作品和季度，再使用唯一匹配的集标题；标题不匹配时按集数查找。
5. 多个同等候选、未知季度或元数据不足时，保留手动选择，避免误配。

首播日期不用于把当前集改配成另一集。片头片尾等 C1/C2 条目不作为正片候选。画面上的匹配提示会显示选中的作品和集名；听到弹幕内容明显不对应时，应先检查集数。

## 桌面手动匹配

1. 播放当前集，打开控制栏中的弹幕菜单。
2. 选择「弹幕搜索」，输入作品名称并回车。
3. 在搜索结果中确认作品及季度；不要只看相似标题。
4. 进入「剧集信息」，选择当前视频真正对应的弹幕集数。
5. 等待加载，查看画面提示并检查开头和中段是否对应。

桌面弹幕菜单还包含「从源添加弹幕」「弹幕源延迟设置」「弹幕样式」「弹幕内容」。菜单中会显示已经关联的作品和集名，便于复核。

## Android 手动匹配

1. 轻触播放画面显示控制栏，点击弹幕入口。
2. 选择「搜索弹幕」，输入作品名。
3. 选择正确作品及集数，等待弹幕出现。
4. 需要管理现有来源时，选择「来源、屏蔽与时间偏移」。

Android 的弹幕菜单还提供「开启／关闭弹幕」「导入 XML / JSON / ASS」「弹幕样式」「添加视频网站来源」。导入文件通过系统文件选择器进行。

## iPad 与 Apple TV 手动匹配

1. 播放时打开控制栏中的「弹幕」。
2. 在「搜索作品」中输入作品名并搜索。动画直接输入名称；其他作品可以按 PC 端格式输入：「名称|tv」表示电视剧，「名称|dy」表示电影。
3. 选择正确的作品和集数，等待弹幕加载。
4. 自动匹配有误时，也可以用「重新匹配当前视频」（Apple TV 为「重新自动匹配」）重新识别。

两端都提供「启用弹幕」开关、已加载来源列表、按来源「提前 0.5 秒」「延后 0.5 秒」和「加载网址」添加视频网站来源；iPad 还可以「从文件导入 XML / JSON / ASS」。开启「同时纠正共享匹配」后，手动选择的集数会提交到共享服务，需要服务器账号有权限。

## 共享校准怎样保存

共享校准保存的是“当前作品、季集与所选弹幕的对应关系”。它帮助后续播放和其他客户端使用同一份正确匹配。

| 用户状态 | 读取共享匹配 | 保存手动校准 |
| --- | --- | --- |
| 普通大河 Emby 登录 | 可以 | 可以，使用当前 Emby 登录 |
| 自建 Emby 用户 | 可以 | 不使用外服 Emby 凭据写入 |
| 只登录独立评论账号 | 可以读取 | 评论账号不提供映射写入权限 |

大河用户无需管理员 JSON、额外令牌或特殊管理员账号。只有明确手动选定作品和集数时才保存；自动识别不会自行把结果当作用户确认的校准。

服务端依据原视频和真实弹幕 ID 处理后续对应关系。客户端不会简单给 ID 加 1 来猜下一集。因此连续编号与分季编号有差异时，先准确选中当前集，再到下一集检查共享结果。

出现「绑定未保存」或「弹幕已加载，但共享匹配未保存」表示本次选择已加载，保存没有成功。先确认仍登录大河 Emby，等待网络或服务恢复后再操作；不要为了消除提示反复选择不确定的条目。

服务提示频率限制时，等待显示的时间。切换集数或局域网／域名入口不会使同一服务的等待时间自动取消。

## 桌面请求超时与自动重试

普通弹幕下载的连接超时为 5 秒、单次请求总超时为 20 秒；共享匹配查询保留 35 秒总超时。发生超时、连接中断或 HTTP 408／502／503／504 时，界面提示等待 1 秒，并自动重试一次。同一请求最多发出两次；仍然失败时显示错误，可稍后手动重新选择。

返回成功但弹幕为空时不会重复请求。HTTP 400／401／403／404 等请求或权限错误也不会自动重试；429 限流会提示等待，内置服务按 `Retry-After` 记录冷却时间。服务端如果把上游异常返回为成功的空结果，客户端无法将它与真正没有弹幕区分，需要服务端返回明确错误。

切换剧集、手动选择其他来源、切换登录身份会取消旧请求及等待中的重试。保存共享校准只提交一次，避免超时后重复写入；保存失败后的普通弹幕读取仍可按上述规则重试。

本节适用于桌面内置弹幕 API 下载和共享查询。Android、iPad、Apple TV 与第三方视频网站来源有各自的请求流程。

## 错集和时间不齐怎样区分

**整段内容与剧情不同：** 优先重新检查作品、季度、集数。时间偏移无法修正选错集。

**内容正确，但整体早几秒或晚几秒：** 调整该来源的时间偏移。弹幕比画面早出现时，让它延后；比画面晚出现时，让它提前。

**前半段正常，中途开始错位：** 可能来自不同剪辑版本、片头片尾长度或删节。桌面可以在「弹幕内容」中使用「调整弹幕延迟」，从选定时间起调整对应来源；先找到错位开始位置再调整。

Android 的来源时间偏移按秒填写，允许 -3600 到 3600 秒。调整后在已知台词处检查结果，避免一次改动过大。

## 来源屏蔽和手动添加

桌面在「从源添加弹幕」管理已有来源，可屏蔽服务返回的来源，或删除自己添加的来源。支持的来源网址按插件实际结果加载；网页站点变动或访问限制可能使某些来源暂时不可用。

Android 在「来源、屏蔽与时间偏移」中管理已有来源；「添加视频网站来源」用于添加链接，系统文件选择器用于本地 XML / JSON / ASS。桌面从来源输入框也可加载支持的本地 XML / ASS 绝对路径。

历史来源的屏蔽状态和时间偏移会保留。明明已加载却看不到弹幕时，先检查是否关闭弹幕、屏蔽了所有来源，或透明度设得过低。

## 样式与流畅度

「弹幕样式」提供字号、粗体、描边、阴影、透明度、滚动时长和显示范围。想避开字幕，可缩小弹幕显示范围，例如只占顶部区域。

滚动时长越短，弹幕移动越快；透明度 0 表示完全透明，1 表示不透明。样式值不改变原视频或字幕。

弹幕刷新受平台、同步方式、显示器和系统呈现影响。高刷弹幕不要求把视频 RIFE 补到同样的帧率；先按正常播放需求配置，再观察实际效果。Windows 用「显示器重采样」时弹幕每次屏幕刷新都移动；用音频时钟时（包括窗口补帧）跟着每一帧画面移动，补到 59.94 帧就是每秒约 60 次，见 [AI 补帧](https://github.com/Tigerest/Tigerest-Theater/wiki/RIFE#windows-的同步方式)。2.9.5.1 起 Windows 弹幕默认用微软雅黑。

未解决的问题见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
