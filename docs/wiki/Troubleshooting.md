# 故障排查与反馈

先记录客户端版本、系统版本、使用安装版还是便携版，以及问题发生在哪个界面。每次改变一个设置并复现，便于看清原因。

## 无法连接服务器

确认完整地址包含正确协议、端口及反向代理子路径。在同一设备、同一网络用浏览器打开该入口：

- 浏览器也打不开：先检查网络、域名、反向代理或服务器状态。
- 登录页能打开但账号被拒绝：联系该 Emby 服务器维护者。
- 局域网正常、外网失败：确认使用的是有效的远程地址。
- 刚升级到 2.9.5 就回到 Emby 登录页：大河专属服务器的公网连接改用了加密连接，网页端需要重新登录一次（Apple TV 不用），服务器列表和设置都在。2.9.4 及更早的版本在旧地址关闭后无法从公网连接，请升级。

更换入口：点顶栏「客户端」按钮，选择「切换 / 管理服务器」。详细地址示例见[服务器与登录](https://github.com/Tigerest/Tigerest-Theater/wiki/Server)。

## 公共评论不显示或要求登录

**已知问题：** 评论服务已停用旧的专属评论接口，2.9.4 及更早版本中大河用户无法发表或回复评论，升级到 2.9.5 后恢复。这不是评论账号的问题，不需要为此注册评论账号。

自建 Emby 用户需要在「评论账号」中注册或登录，才能读取和发送公共评论。Emby 已登录不等于独立评论账号已登录。

大河用户应自动取得评论身份；如果失败，先确认 Emby 登录仍有效，再刷新评论。不要为一次自动登录失败重复注册无关账号。

媒体缺少可靠 TMDB、集序未知或属于不支持的 DVD／合并集时，会提示不能关联公共话题。大河会继续使用原有作品讨论；自建用户应检查媒体元数据。

服务不可用时稍后重试。内置社区服务走 HTTP，网络或防火墙需要放行；媒体播放服务与评论服务并非同一个可用性判断。

## 头像不更新

先确认改的是当前 Emby 账号的本人头像，再发送一条实际需要发表的评论或回复，触发头像检查。服务端可能异步同步，稍后点「刷新评论」。

若评论已成功但头像失败，点「重试头像同步」，不要重复发送正文。读取自己 Emby 的头像失败时保留旧图；不会误清空。多设备更新冲突时等待资料刷新，下次发言再同步。

如果页面仍显示旧服务的密码范围或不支持头像，按页面能力提示使用；不要手动修改客户端校验规则。

## 弹幕为空、错集或错时

先确认弹幕开关、来源屏蔽、透明度及当前集的匹配提示。错集重新「弹幕搜索」并选集；内容正确但整体错时，调整来源偏移。

「绑定未保存」只说明共享保存失败，本次手动弹幕仍可加载。大河用户检查登录及网络；独立评论账号不提供共享绑定写入权限。

自动匹配找不到时，可更换作品搜索词并手动确认季度。具体步骤见[弹幕教程](https://github.com/Tigerest/Tigerest-Theater/wiki/Danmaku)。

## 无声或重启后音量为 0

依次检查播放器音量、静音、系统媒体音量、输出设备和当前音轨。使用直通时，确认功放／输出连接支持所选格式。

2.6.0 修复了退出时音量单位错误，并在新音量记录首次初始化时将旧版遗留的 0 恢复为 100；之后手动设为 0 会保留。首次安装也默认 100。若使用早期预览包，请更新到当前正式版后再验证。

## 已知问题：Windows 窗口播放持续掉帧

部分 Windows 高刷新率环境中，窗口模式会持续卡顿，播放诊断里的输出丢帧不断增长，全屏播放则正常。该问题在 RTX 4090、240 Hz、GPU-Next / D3D11、关闭 RIFE 的实际播放中已复现；不表示所有 Windows 设备都会遇到。

**2.9.5.1 仍保留此已知问题，临时处理是使用全屏播放。** 当前证据指向窗口呈现与显示同步，底层原因和正式修复仍待确认。切换音频时钟在实验中停止新增丢帧，但弹幕插件会调整同步模式，因此不把它作为已经完成的通用修复，也不建议为此盲目修改驱动或系统设置。

开启 RIFE 补帧时不受这个问题影响：窗口补帧用音频时钟，不用显示器重采样。2.9.5.1 起音频时钟下每一帧都对准屏幕刷新提交，窗口补帧 3 次、5 次刷新的交替大幅减少，见 [AI 补帧](https://github.com/Tigerest/Tigerest-Theater/wiki/RIFE#windows-的同步方式)。

反馈时请说明显示器刷新率、窗口／全屏的差异，并观察稳定播放后的新增丢帧。调查记录见[窗口呈现诊断](https://github.com/Tigerest/Tigerest-Theater/blob/main/docs/reports/2026-10-13-windowed-presentation-diagnosis.md)。

## 已知问题：Mac 保存 mpv.conf 后 SVP 连不上

Mac 上本次运行中开始播放过以后，在设置里保存 mpv.conf 会丢掉 SVP 的连接设置，SVP 要到下次打开客户端才能重新连上。2.9.4 起就有这个问题，2.9.5 仍未修复；保存后退出并重新打开客户端即可。

## 播放报 401 或打不开

2.8.0 修复了服务器给出的播放地址不带令牌时报 401 的问题（服务器关闭了 Emby 的 AddApiKeyToDirectStreamUrl）。仍然报 401 或 403 时：

- 确认 Emby 登录没有过期：退出后重新登录再试。
- 在同一服务器的 Emby 网页端播放同一部影片对照。网页端也失败时，是服务器、账号权限或网盘链接的问题，请联系服务器维护者。
- 服务器把播放请求 302 跳转到网盘或 CDN 时，客户端不会把 Emby 令牌带给跳转后的主机；需要令牌才能访问的跳转地址应由服务器签名。

## 一起看连不上或不同步

- **看不到入口：** 只在大河服务器上提供，Apple TV 暂不支持。确认已登录大河 Emby。
- **提示「正在重新连接一起看服务」：** 客户端会自动重连；断线超过 60 秒会失去座位，重新用房间码加入即可。
- **提示「一起看服务已更新，请升级客户端后再加入」：** 更新到最新版客户端。
- **两边进度相差明显：** 稳定播放几秒后会自动对齐；持续不齐时退出播放器，在房间页点「进入播放」。反馈时写明各成员的平台、是否开启 RIFE 和大致相差的秒数。

更多说明见[一起看](https://github.com/Tigerest/Tigerest-Theater/wiki/Watch-Together)。

## 视频卡顿、花屏或只有声音

先用同服务器另一段普通视频对照，并查看网络是否持续缓冲。关闭 RIFE 和高负载画质预设后再比较，可以判断是否由处理负载导致。

花屏可暂时关闭硬解对照。桌面渲染兼容问题可尝试「libmpv Render API 兼容模式」，更改后重启。

切集异常时记录进入播放的方式、队列内容、上一集／下一集的目标及是否发生黑屏。不要把累计丢帧数直接当作当前持续掉帧；稳定播放一段时间，观察数字是否还增长。

## RIFE 没有生效

核对扩展安装状态、完全重启、当前片源格式和速度。更改模型／目标后要重新打开视频。2.9.4 起不再有配置模式；mpv.conf 里改帧率的 vf 滤镜和 `interpolation=yes` 会在开启 RIFE 时自动暂停，设置页底部会提示。

准备引擎时显示暂停与进度属于正常过程；真正失败会显示原因。持续丢帧时先降低目标、换 lite 或减轻画质负载。详见 [RIFE 教程](https://github.com/Tigerest/Tigerest-Theater/wiki/RIFE)。

## 更新或运行库错误

Windows 请完整安装或完整解压，避免只复制 EXE 或混用旧 DLL。旧版内置下载失败时，手动下载当前正式包覆盖安装一次。

便携版保留 `data`，Mac 替换完整应用包，Android 使用同签名正式包，iPad／iPhone 和 Apple TV 用原来的签名身份重新签名后覆盖安装。iPad 从 2.9.3 及更早的 `ipad.ipa` 换到 2.9.4 的 `universal.ipa` 时会作为新应用安装，登录和设置需要重新来，这不是安装失败。校验失败时重新下载；系统架构或版本不满足要求时，应先核对[安装要求](https://github.com/Tigerest/Tigerest-Theater/wiki/Installation)。

Windows 媒体库页面闪烁／花屏时，确认完整更新。仍有异常可在完全退出后用 `"Tigerest Theater.exe" --disable-gpu` 比较网页 GPU 渲染；这与视频硬件解码是独立设置。

Mac 来源拦截按「系统设置 → 隐私与安全性」处理，前提是已确认来自本项目。不要把来源提示当作 RIFE 格式不支持。

iPad／iPhone 或 Apple TV 的应用突然打不开时，先检查签名是否过期：免费 Apple 账号的签名有有效期，过期后需要重新签名安装。

## 日志在哪里

| 安装方式 | 日志目录 |
| --- | --- |
| Windows 安装版 | `%LOCALAPPDATA%\Tigerest Theater\profiles\<profile-id>\logs\` |
| Windows 便携版 | `程序目录\data\profiles\<profile-id>\logs\` |
| Mac | `~/Library/Logs/Tigerest Theater/profiles/<profile-id>/` |
| Android、iPad／iPhone | 使用「上报问题」附带应用内诊断日志，无需连接电脑 |

保留出错时间附近记录，避免发送整个用户数据目录。公开反馈前检查并移除密码、令牌、私人网址和个人信息；评论错误中的请求编号可以帮助定位。

## 怎样提交有效反馈

大河的某部作品、字幕或播放资源问题，用详情页「上报问题」，见[消息与报错](https://github.com/Tigerest/Tigerest-Theater/wiki/Messages-and-Reports)。客户端本身的问题提交[GitHub Issue](https://github.com/Tigerest/Tigerest-Theater/issues)。

建议按下面格式提供：

```text
客户端版本：
系统版本 / 设备：
安装版或便携版：
发生位置与操作步骤：
期望结果：
实际结果 / 完整错误文字：
是否每次出现：
相关设置（如 RIFE 模型、目标、渲染后端）：
出错时间与脱敏日志：
```

播放问题再附分辨率、帧率、编码、SDR/HDR 和音轨／字幕信息。清楚说明是界面操作、真实视频播放还是只在某一部影片复现，有助于缩小范围。
