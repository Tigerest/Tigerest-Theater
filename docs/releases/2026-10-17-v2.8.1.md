# Tigerest Theater 2.8.1 · Windows 与 Android

修复 Windows 与 Android 首页里同一部作品出现两次。Mac、iPad 与 Apple TV 的 2.8.0 补充附件已经带上同一修复，本次不发布新的 Apple 安装包。其余功能与 [2.8.0](2026-10-16-v2.8.0.md) 相同。

## 首页同一作品出现两次

服务器上同一部作品有时存在两个剧集条目，例如重新整理过媒体库，或同一部剧放在两个路径下。两个条目的 Item Id 不同，Emby 给它们相同的作品身份（`PresentationUniqueKey`）。2.8.0 的 Windows／Android 首页只按 Item Id 去重（单集归到所属剧集），两个条目各自有观看记录时，「继续观看」里会并排出现两张同一作品的卡片。

2.8.1 的首页按「类型＋服务器提供的作品身份」合并，没有作品身份的条目仍按 Item Id 区分：

- 继续观看的进度条和继续播放的那一集，取两个条目中最近一次播放的记录；看完的新记录会替代另一个条目上已放弃的进度。
- 最近入库时间和首页大图标出的新一集，取两个条目中较新的一个。
- 继续观看、最近添加、评分和上映日期四种排序都在合并后计算数量，不会因为重复条目而少显示作品。
- 读取剧集信息时请求 Emby 不按作品身份分组；否则 Emby 只返回同组中的一个 Id，另一个条目拿不到作品身份，无法合并。

客户端只按服务器给出的作品身份合并，不按标题合并：同名的不同作品（例如翻拍）仍然分别显示。如果服务器上两个条目的作品身份本身不同，客户端不会合并，需要在服务器上合并条目或修正元数据。

这项改动在 Windows 与 Android 共用的网页首页（`native/homeData.js`）里，与 2.8.0 苹果三端首页的修复相同。

## 其他

- Windows RIFE 扩展的兼容版本名单加入 2.8.1，已安装的扩展继续可用，不需要重新下载。
- 共用网页里还带上了 2.8.0 苹果补充版对 iPad 一起看的调整（后台暂停同步、开启 RIFE 时只用跳转校正）；这些只对 iPad 生效，Windows 与 Android 的一起看行为不变。
- Android 原生部分（播放器、原生库、签名）与 2.8.0 相同。

## 验证范围

- **首页去重（模拟数据）：** `tests/test_home_orders.js` 20 项全部通过，其中 6 项覆盖同一作品的两个条目：继续观看与看完记录合并、最近添加与继续观看合并、同名不同作品保持分开、看完的新记录替代旧进度、评分／上映日期排序在截取前去重、分页按合并后的作品计数。同样的测试用在 2.8.0 的 `homeData.js` 上失败，例如返回两张卡 `['show', 'alias']`。
- **真实服务器：** 在 Windows 上用隔离配置运行本地构建的 2.8.1 客户端，登录大河服务器，打开「1啊你妹」首页（继续观看排序，24 部作品）：「转生成为魔剑」和「乱马½」各只出现一次，观看进度（15/15、26/26）和按最近观看的排序位置保留。服务器上这两部各有两个剧集条目（不同目录、Item Id 不同、作品身份相同）。在同一会话、同一份数据上运行 2.8.0 的首页逻辑作对照，两部各出现两次，另有一部作品也重复；2.8.1 没有重复。这两部都已看完，没有未看完的单集，所以合并后保留进度条的情形只由模拟数据测试覆盖。
- **Windows：** 本地 RelWithDebInfo 构建，安装到暂存目录后运行完整 CTest，两轮都是 98 项中 89 项通过；另外 9 项是开启 GPU 或可见窗口的 WebEngine 界面测试（首页、单集转场，外观，表单，更新，设置，内容边距），在测试机无人操作时等待页面超时，在有人操作时用同一构建单独重跑 9 项全部通过。这些测试和被测代码与 2.8.0 相同；发布以最终发布构建的完整 CTest 为准。客户端内嵌的 `homeData.js` 与仓库文件逐字节一致。
- **Android：** 116 项 JVM 测试全部通过，lint 无错误；`verify_apk.py` 检查 20 个原生库的哈希和 16 KB 对齐；debug 与 release 安装包里的 `homeData.js` 与仓库逐字节一致，版本为 2.8.1（versionCode 2080100）。未在 Android 真机上运行。
- 最终构建的测试、签名与附件哈希以发行页的 `TigerestTheater-2.8.1-RELEASE-MANIFEST.json` 与 SHA-256 清单为准。

## 已知问题

- 部分 Windows 高刷新率环境下，窗口播放可能持续卡顿、增加输出丢帧，而全屏正常。2.8.1 仍未修复；请先使用全屏播放。详见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
- 真实媒体库里剧集页进入详情时仍可能出现 80–270 ms 的单帧停顿，来自网页端主线程工作，后续优化。
