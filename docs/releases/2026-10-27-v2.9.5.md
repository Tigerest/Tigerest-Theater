# Tigerest Theater 2.9.5 · 本地播放器与加密连接

本次 Windows、Android、Mac、iPhone／iPad 与 Apple TV 一起发布。Windows 沿用 2.9.4 的修补版 QtWebEngine（六个补丁）；Android 的 JNI 原生库与 2.9.0 相同；Mac 沿用 2.9.4 的修补版 QtWebEngine 和打包的运行库。

> **升级须知：** 大河专属服务器的公网连接改用加密连接。Windows、Mac、Android、iPhone 与 iPad 升级后第一次打开需要重新登录一次 Emby，Apple TV 不用。旧版客户端使用的公网地址还会保留一段时间，之后关闭；关闭后 2.9.4 及更早的版本无法从公网连接，请尽快升级。

## 本地播放器（Windows）

- **直接播放本地视频：** 在资源管理器里对视频文件右键「打开方式」选大河影院，或把视频拖到大河影院的快捷方式上，不用连接媒体服务器就能播放。安装版会把大河影院加进 mkv、mp4、mov、avi、ts、m2ts、rmvb 等 24 种视频格式的「打开方式」列表，不改动现有的默认播放器；想默认用大河影院打开，在 Windows 的「默认应用」里选择即可。便携版不注册「打开方式」，可以把视频拖到程序或它的快捷方式上。
- **播放列表：** 单独打开一集时，同一文件夹里的视频按文件名排成播放列表（第 2 集在第 10 集前面），从打开的这一集开始播，播完自动接下一集；一次选中多个文件打开时，列表就是选中的这些文件。控制栏的播放列表、上一个／下一个，以及任务栏缩略图和键盘媒体键的上一个／下一个，都在这个列表里切换。
- 大河影院已经开着时再打开文件，会交给已经打开的窗口播放，不会多开一个。
- 服务器选择页和客户端菜单新增「打开本地视频」，快捷键 Ctrl+O。
- **不使用在线服务：** 本地播放不搜索、不加载弹幕（弹幕按钮隐藏），不上报播放进度，也没有评论和一起看。用视频文件启动时不会自动连接上次的服务器；需要媒体库时，在选择页点要连接的服务器。
- 正在播放服务器上的视频时打开本地文件，原来的播放先正常结束，进度照常保存，本地文件的播放不会记到那个条目上。
- 音轨和字幕由 mpv 自动选择，和视频同名的外挂字幕（如 `.srt`、`.ass`）会自动加载。列表最后一个播完或停止后回到服务器选择页；打不开的文件会提示文件名，并接着播下一个。
- 修复 mpv 不经过客户端、自己换到另一个文件时（例如从 uosc 的文件浏览里选择）只有声音、画面黑屏。

## 本地播放器（Mac）

- 在访达里对视频选「打开方式 → 大河影院」，或把视频拖到程序坞里的大河影院图标上，不用连接媒体服务器就能播放。和 Windows 一样，24 种视频格式只加进「打开方式」，不改动默认播放器；想默认用大河影院打开，在视频的「显示简介 → 打开方式」里选择后点「全部更改」。
- 播放列表、不使用在线服务、打不开的文件提示文件名等规则和 Windows 相同；大河影院已经开着时再打开文件，交给已经打开的窗口播放；在访达里一次选中多个文件打开，列表就是这些文件。
- 「打开本地视频」的快捷键是 ⌘O，播放器设置是 ⌘,。

## 服务器播放选集（Windows、Mac、Android、iPhone 与 iPad）

- 从剧集页点「播放」继续看下一集时，Emby 只把这一集排进播放队列，播放列表里也只有这一集，没法选别的集（2.9.4 及以前也是这样）。现在队列里只有一集时，播放列表列出这一季的各集并标出当前集；在列表里选别的集，或按上一个／下一个（包括 Windows 任务栏和键盘媒体键），都会从那一集开始播放。队列里本来就有多集时，仍按 Emby 的队列。
- Apple TV 播放时本来就列出整季，现在不再列出服务器上缺失的集。

## 页面转场（Android）

- **0.7 秒内可以操作：** 点下海报或媒体库后，下一个页面在 0.7 秒内就能操作。在小米 MIX Fold 4（120 Hz）上连接局域网 Emby 实测：首页→详情、海报墙与详情之间约 0.61–0.68 秒，首页→媒体库约 0.58–0.64 秒，返回首页约 0.35–0.39 秒（2.9.4 约 0.95–2.2 秒）。
- **按下就起飞：** 海报按下后 6–40 ms 就开始移动，飞行方式和桌面相同，旧页面被盖住后就换到新页面，不再先抬起海报、等新页面稳定再飞。返回首页时一按下就换页，首页露出来就能操作，画廊的入场动画接着播。进媒体库时，真实的海报墙随着放大动画进来，不再复制一面还在加载的墙。
- **背景光晕：** 页面背景的模糊光晕改为预先画好的小图（和 Mac 相同）。以前每次切页都要整片重新绘制，GPU 线程约 180 ms，这是飞行途中卡顿的主要原因。
- **不再闪烁：** 逐帧检查录屏找到的四处闪烁都已修复：返回时海报空白三帧、落地时卡片或详情海报空白一帧、按下的首页封面位置在起飞时空白三帧、滚动过的海报墙飞出时变成列表顶部的空白。最后一处在各平台共用的转场脚本里，桌面一并修复。
- 首页封面的图片提前在解码线程里解好，按下就能起飞；Emby 图片的缓存在 Android 上也能直接复用。

## 离线媒体与设置（Windows 与 Mac）

- 修复播放离线下载的视频时没有声音和字幕：离线播放改用本地播放流程，自动选择音轨和字幕，同样不加载弹幕、不上报进度。
- 没有连接服务器时也能打开完整设置：服务器选择页新增「设置」按钮。
- 独立打开的设置窗口改为和连上服务器时一样的左侧分组菜单：「播放器设置」（客户端、视频、音频、字幕、MPV 画质与插件、弹幕样式）在前，「媒体库设置」在后；窗口较窄时改用同样分组的下拉菜单。

## 播放统计（Windows 与 Mac）

- mpv 统计信息的第 2 页（帧耗时）默认在各渲染步骤的数字旁画出最近的耗时曲线。在 4K 240 Hz 屏幕、默认着色器档位下实测，曲线每帧只多用约 17 µs 的叠加层 GPU 时间。

## 客户端信息（所有平台）

- 注册或登录评论账号、用 Emby 账号登录评论、创建一起看房间，以及向大河弹幕服务请求弹幕时，附上客户端名称、版本和平台（例如 Tigerest Theater 2.9.5 Windows），后台据此记录用的是哪个客户端。平台分别为 Windows、macOS、Android、iOS（iPhone）、iPadOS 和 tvOS；Apple TV 没有一起看。不包含设备标识、账号或密码；向其他弹幕源请求时不附带。

## 加密连接（所有平台）

- 大河专属服务器的公网连接改用 HTTPS：Emby 页面、评论、弹幕、一起看和检查更新都走加密连接。在 NAS 所在的局域网里仍然直接连接，不受影响。iPhone、iPad 与 Apple TV 在系统层面也不再允许以明文连接公网服务。
- 升级后第一次打开会换到新的加密地址。Windows、Mac、Android、iPhone 与 iPad 需要重新登录一次 Emby（新地址对网页来说是另一个网站，原来保存的登录不会带过来）；服务器列表、设置和离线媒体都保留。Apple TV 的登录会自动换到新地址，不用重新登录。
- 自建服务器模式里手动填写的地址不会被改动。
- 旧版客户端使用的公网地址还会保留一段时间，之后关闭；关闭后 2.9.4 及更早的版本无法从公网连接，请尽快升级。

## 版本号与构建号（所有平台）

- 之后的小修复用四段版本号（例如 2.9.5.1），可以只给需要的平台发修复版，不必全平台一起升级。2.9.5 起检查更新能识别这类版本，没有当前平台安装包的修复版不会提示；2.9.4 及更早的版本识别不了，需要先升级到 2.9.5。Apple TV 没有应用内更新检查。
- 更新窗口在「当前版本」下面显示构建号，方便确认装的是哪个包：Windows 和 Mac 为提交编号和构建日期，Android 为版本代码和提交编号，iPhone 与 iPad 为构建编号和提交编号。Android 版本代码的末两位就是第四段版本号（2.9.5 为 2090500，2.9.5.1 为 2090501）。

## 安装

- `TigerestTheater-2.9.5-x64.exe`：Windows 安装版；或完整解压 `TigerestTheater-2.9.5-x64.zip` 便携版（保留 `data`）。从 2.9.4 起，在更新窗口点「安装更新」会自动关闭、静默安装并重新打开；从 2.9.3 及更早版本升级时完全退出客户端后运行安装向导。未做 Authenticode 签名。
- `TigerestTheater-2.9.5-android.apk`：Android 15+，沿用原签名，可覆盖升级。
- `TigerestTheater-2.9.5-arm64.dmg`：Apple Silicon Mac，macOS 26+。打开后把应用拖入「应用程序」替换旧版；Mac 2.9.4 的更新窗口会找到这个文件。使用 ad-hoc 签名，未经 Apple 公证。2.9.4 的 DMG 标着支持 macOS 15，实际打包的库需要 macOS 26；2.9.5 直接标明需要 macOS 26。
- `TigerestTheater-2.9.5-universal.ipa`：iPhone 与 iPad 通用（iOS／iPadOS 26+），应用标识与 2.9.4 相同，可以覆盖安装；`TigerestTheater-2.9.5-tvos.ipa`：Apple TV（tvOS 26+）。IPA 不含签名，需要用自己的 Apple 身份签名后安装；两种包不能互换。见 [iPad / iPhone 安装说明](https://github.com/Tigerest/Tigerest-Theater/blob/main/docs/apple/INSTALL.md)与 [Apple TV 安装与构建](https://github.com/Tigerest/Tigerest-Theater/blob/main/apple/TV/README.md)。
- `TigerestTheater-2.9.5-SHA256SUMS.txt` 校验本页全部文件；`RELEASE-MANIFEST.json` 记录各平台的来源提交和验证范围。源码：`client-Sources.zip`（全部客户端，含 Mac、iPhone／iPad 与 Apple TV）、`android-Sources.zip`（及 `android-SOURCE-MANIFEST.json`）。
- 本版 Windows 使用的修补版 QtWebEngine 与 2.9.4 相同，组件包见 [2.9.4 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.4)的 `TigerestWebEngine-6.9.3-d3d11.zip`。
- 无法访问 GitHub 时，可从[夸克网盘](https://pan.quark.cn/s/88e6f7a795b4)或[百度网盘](https://pan.baidu.com/s/58azzOU4piiB3miyZqA1dig)的 `2.9.5` 文件夹下载同样的 Windows／Android 安装包，用 `SHA256SUMS.txt` 校验。Mac、iPad 与 Apple TV 的安装包目前只在 GitHub 发行页提供。
- 已安装的 Windows RIFE 扩展可以继续用于 2.9.5。

## 验证范围

- **Windows 发布构建：** 安装包、便携包和 Android 包都从 `2d57361` 构建（发布提交只加文档）。完整串行 CTest 122 个目标首轮全部通过（605 秒）；条件跳过与 2.9.4 相同（需独占桌面指针的窗口测试、需私有 RIFE 运行库的测试，以及默认关闭的联网用例）。另外单独开启的联网用例：社区版本列表经 HTTPS 新地址线上验签通过（30 个版本，最新为 v2.9.4）。
- **Windows 安装包：** 便携包 1534 个文件与暂存目录逐字节一致，OpenSSL、mpv 与修补版 QtWebEngine（六个补丁）的哈希与锁定值一致。解压到空目录、只保留系统目录 PATH，用一个本地测试视频启动：Qt、WebEngine 与 mpv 都从包内加载，D3D11 fence 同步就绪，画面和同名外挂字幕正常，87 个内置着色器为 LF 换行。以 System32 为工作目录先启动一次，再带文件启动第二个进程（和资源管理器「打开方式」相同），第二个进程 601 ms 后把文件交给已打开的窗口并退出，首个窗口开始本地播放。更新窗口显示「当前版本 2.9.5」和「构建号 2d573614 · 2026-10-27」，经 HTTPS 新地址在线检查完成。
- **本地播放器（Windows）：** 上一轮在隔离配置中用真实客户端逐项检查过：带文件启动不连服务器、同文件夹按名排序、自动下一集、多文件队列、第二实例转交、播完／停止回选择页、离线播放、打不开的文件提示、Ctrl+O。资源管理器「打开方式」以 System32 为工作目录启动客户端的情况，在隔离的便携副本上复现并验证（见上）。这一轮 Windows 相关代码没有改动，只重跑了上面的冒烟检查。
- **加密连接：** 网页测试、C++ 与 Lua 弹幕测试、Android JVM 测试都改用新地址；保存了旧公网地址的专属服务器配置会换到新地址（Windows、Android 单测，iPhone 模拟器实测）。反向检查：去掉旧地址改写、把四段版本比较改回三段，对应测试会失败。生产接口只收到只读请求：检查更新、以及上一轮确认三个客户端信息头已被允许的预检请求。

- **没有测的：** 所有平台都没有在新地址上用真实账号登录后再测评论、一起看和弹幕；macOS 15 没有机器可测。

## 已知问题

- 部分 Windows 高刷新率环境下，窗口播放可能持续卡顿、增加输出丢帧，而全屏正常。2.9.5 仍未修复，请先使用全屏播放，见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
- Mac：本次运行中开始播放过以后，在设置里保存 mpv.conf 会丢掉 SVP 的连接设置，SVP 要到下次打开客户端才能重新连上。2.9.4 起就有这个问题，2.9.5 仍未修复。
- 本地播放还不能把文件直接拖进已经打开的窗口（Windows 拖到程序图标或快捷方式上、Mac 拖到程序坞图标上可以），也不记录本地文件的续播位置。
- 返回一面这次还没显示过、图片也不在缓存里的海报墙时，服务器要 0.5–0.8 秒才给出目标卡片，转场约在 0.8–0.9 秒结束。
- Android 的多数转场里仍有一到三帧晚到（16.7–33 ms）；重新载入后第一次从首页进详情，最长会停顿约 0.1–0.26 秒。
- Android 返回首页时，首页封面还在解码，会一张张出现。
