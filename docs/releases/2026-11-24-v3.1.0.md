| Android | [3.1.0 APK][dl-android] | Android 15+，arm64-v8a / x86_64 |

Windows 与 Android 更新到 3.1.0。Mac、iPhone／iPad 与 Apple TV 这次没有新版本，仍用 [3.0.0](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v3.0.0)。

## 首次使用引导（Windows 与 Android）

- 新安装或新建配置后，客户端用一段引导介绍媒体库、推荐海报、作品列表、作品页、一起看、评论区、客户端菜单、消息和播放器，Windows 还有专业模式和补帧：页面变暗，正在讲的部分保持亮着，旁边的气泡写着标题、两三行说明和进度，用「上一步」「下一步」翻页。
- 新安装和新配置要看完引导（Esc 和返回键回到上一步）；从旧版升级后也会出现同一段引导，可以点 × 跳过。「客户端 → 客户端设置 → 重新打开引导」随时再看一遍。
- Windows 的「播放器」「专业模式」「补帧」三步配有真实客户端的截图，图上的编号和说明对应；窗口太小放不下图时只显示文字。Android 的播放器一步讲手势。
- 页面上没有的部分（例如还没有作品、窗口太窄时收起的顶栏按钮）直接跳过，进度跟着变。开始播放或离开页面会中断引导，下次回到首页时重新开始。

## 第三方弹幕服务（#44）

- Windows 的「设置 → 弹幕样式」新增「弹幕服务地址」：留空照旧使用大河弹幕服务；也可以填写兼容弹弹play API 的第三方弹幕服务，例如自己部署的 [misaka_danmu_server](https://github.com/l429609201/misaka_danmu_server) 或 [danmu_api](https://github.com/huangxd-/danmu_api)。地址可以带路径，比如部署时设的令牌。
- 可以填多个接口，按顺序用逗号分隔，地址后可以用 `|` 或 `#` 加备注。自动匹配同时查询所有接口；手动搜索按填写顺序列出各接口的结果。填写后只使用列出的接口；共享匹配和共享校准只来自大河弹幕服务。
- 设置页会检查地址：带账号、查询参数或缺少 `http(s)://` 时提示原因，不保存。新地址从下一个视频开始使用。第三方服务只收到匹配要用的作品名、集数和「从源添加弹幕」里填的网址，收不到 Emby 登录信息或大河账号。
- Android 原来就有这一项，仍只读取一个地址；说明里补上了地址可以带路径。
- 详细说明见 [弹幕](https://github.com/Tigerest/Tigerest-Theater/wiki/Danmaku#使用第三方弹幕服务)。

## NVIDIA VFG 帧生成不再需要 RIFE 扩展（Windows）

- 安装包自带 VFG 用的 Python 3.13.15 和 VapourSynth R79（程序目录的 `vapoursynth`，约 32 MB，许可文件在 `licenses\vapoursynth`），没装 RIFE 扩展也能用 VFG。装了 RIFE 扩展时，VFG 仍用扩展里同一版本的 VapourSynth。安装版因此从约 377 MB 增大到约 389 MB，便携包从约 502 MB 增大到约 518 MB。
- 没有 RIFE 扩展时，显卡是否支持 VFG 改为直接问 NVIDIA 驱动。不能用时设置页写明原因，例如显卡不是 RTX 40／50 系、没有找到 NVIDIA 的驱动。
- RTX 视频超分辨率（VSR）和 RTX Video HDR 由显卡驱动通过 mpv 的 d3d11vpp 滤镜处理，一直不需要 RIFE 扩展。

## 全屏显示器（Windows）

- 「设置 → 指定全屏显示器」选了另一块屏幕时，全屏以前留在窗口所在的屏幕，退出全屏时窗口才跳到选中的屏幕；刷新率又按选中的屏幕设置，两块屏幕刷新率不同时会大量丢帧。现在全屏直接出现在选中的屏幕上，退出后窗口回到原来的位置，播放内核也按这块屏幕读取刷新率和 ICC 配置。

## 专业模式与着色器（Windows）

- 「信号」卡片的「显示」一行在刷新率后面加上显卡送给这块屏幕的位深度和编码，例如「240.00 Hz · 10 bit RGB」，可以看出 10 bit 视频是否真的送到屏幕，或者 HDR 是否因为线材带宽不够只能输出 8 bit。
- 首次编译超过 5 秒的着色器（例如 ArtCNN C4F32 约 110 秒、C4F16 约 16 秒），在着色器库、「＋」选择列表、专业模式和 AI 指南里注明「首次启用要编译约 N 秒，期间画面停住，之后有缓存」。时间是在 i9-14900K 上测的。
- 播放内核修正了 libplacebo 在 Direct3D 11 上分配常量缓冲区的方式：FSRCNNX_x2_56_16_4_1 和四个 ArtCNN_Legacy_C4F32 着色器以前在 Windows 上编译失败（「Too many constant buffers in shader」），现在可以正常使用。原来能编译的着色器得到同样的结果，已有的着色器缓存继续有效。

## 安装

- `TigerestTheater-3.1.0-x64.exe`：Windows 安装版；或完整解压 `TigerestTheater-3.1.0-x64.zip` 便携版（保留 `data`）。在 2.9.4 到 3.0.0 的更新窗口点「安装更新」会自动关闭、静默安装并重新打开；从 2.9.3 及更早版本升级时完全退出客户端后运行安装向导。未做 Authenticode 签名。因为带上了 VFG 用的 Python 和 VapourSynth（解压后约 32 MB），安装版约 389 MB（3.0.0 是 377 MB），便携包约 518 MB（3.0.0 是 502 MB）。
- 已安装的 Windows RIFE 扩展可以继续用于 3.1.0，不用重新下载。播放内核换成了带常量缓冲区修正的新构建，原始构建产物 `Tigerest-mpv-rife-x64-a9f213f.zip` 在本页；修补版 QtWebEngine 与 2.9.4 到 3.0.0 相同，组件包见 [2.9.4 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.4)的 `TigerestWebEngine-6.9.3-d3d11.zip`。
- `TigerestTheater-3.1.0-android.apk`：Android 15+，沿用原签名，可以覆盖安装 3.0.0 和 2.9.5，登录和设置保留。Android 3.0.0 和 2.9.5 的检查更新会提示 3.1.0，下载完成后交给系统安装（系统不允许更新后自动重新打开，装好后请手动打开）。
- `TigerestTheater-3.1.0-SHA256SUMS.txt` 校验本页全部文件；`RELEASE-MANIFEST.json` 记录来源提交、内核来源和验证范围。源码：`client-Sources.zip`（标签 `v3.1.0` 对应的提交）、`android-Sources.zip`（及 `android-SOURCE-MANIFEST.json`）。
- 无法访问 GitHub 时，可从[夸克网盘](https://pan.quark.cn/s/88e6f7a795b4)或[百度网盘](https://pan.baidu.com/s/58azzOU4piiB3miyZqA1dig)的 `3.1.0` 文件夹下载同样的 Windows／Android 安装包，用其中的 `TigerestTheater-3.1.0-SHA256SUMS.txt` 校验。Windows 和 Android 更新窗口的网盘按钮会直接打开这个文件夹。

## 验证范围

- **发布构建：** Windows 安装包、便携包和 Android APK 都从 `0c43be6` 构建。发布构建的完整 CTest 132 项全部通过。
- **安装包：** 便携包 1610 个文件与暂存目录逐字节一致；OpenSSL、播放内核（两个 DLL 角色是同一份）、修补版 QtWebEngine、NVIDIA 的 5 个 DLL 和 VapourSynth 的 59 个文件都与锁定值一致。和 3.0.0 的便携包逐文件比较：新增 62 个文件（VapourSynth 的 59 个文件，加上 3 个许可和锁定文件），原有文件里不同的只有主程序、两个播放内核 DLL、内核的锁定文件和 VFG 脚本（只改了注释）。主程序版本 3.1.0，构建号 `0c43be67`，构建日期 2026-11-24。
- **新播放内核：** 在开发机（RTX 4090、4K 240 Hz）上按内核的验收流程测试：真实 EOF／色彩和 TensorRT 流式测试连续 10 轮通过，播放器生命周期、mpv 早／晚激活、VapourSynth 和 TensorRT 帧图测试都通过。1080p 23.976 fps 真实片源，三个 RIFE 模型各播 600 秒（4K 输出、2.5 倍、跟随音频、默认 3 个着色器），全程在补帧、没有性能回退：lite 和 heavy 稳态没有丢帧，音画偏差最大 0.09 ms 和 0.04 ms；4.25 稳态丢 101 帧（0.29%），集中在三次突发，音画偏差最大 40 ms。测试时机器上还开着另一个客户端；同样条件下用 3.0.0 的内核再跑 4.25，也有丢帧突发（16 帧，出现在别的时间点），所以突发来自机器，不是内核。这台机器上，跑播放器的测试程序每次都在测完、退出时崩在 Qt 的 `qwindows.dll`，换成 3.0.0 的内核和 10 月的测试程序也一样，客户端本身没有这个问题。用新内核重测全部 87 个内置着色器的首次编译，没有失败的；以前报「Too many constant buffers in shader」的 5 个现在每一步都出画面。
- **着色器（真实客户端）：** 发布构建和便携包上，在窗口里播放 960×540 的片段，在专业模式里分别挂上 ArtCNN_Legacy_C4F32_YCbCr、ArtCNN_Legacy_C4F32_RGB 和 FSRCNNX_x2_56_16_4_1：每个都在 2–7 秒内编译完，处理顺序多出 54–55 个渲染步骤，日志里没有编译错误。
- **VFG 不装 RIFE 扩展：** 发布构建和便携包各用一个没有 RIFE 扩展的隔离配置，播放 1080p 23.976 fps 片段，在专业模式里打开 VFG（「高」档，2.5 倍）：VapourSynth 从程序目录（便携包是解压目录）的 `vapoursynth` 加载，显卡算力 8.9 直接从 NVIDIA 驱动读到；输出约 60 fps，每秒生成 42–50 帧，每帧 12–14 ms，没有被关掉。便携包解压到新目录，在没有开发环境的进程里运行（PATH 只留系统目录，不设 Qt、Python 和 VapourSynth 的环境变量）。
- **装了 RIFE 扩展：** 发布构建，隔离配置里放入已安装的 RIFE 扩展：VapourSynth 仍用扩展里的那份；RIFE 4.25（2.5 倍）实时补帧（1.00 倍速，每秒处理 24 对源帧、生成 48 帧），之后在专业模式里打开 VFG，它接替 RIFE，同样跑在扩展的 VapourSynth 上，输出约 60 fps，每帧约 12.8 ms；关掉 VFG 后滤镜链清空（这一集的 RIFE 已经让出）。
- **Android：** APK 用原证书签名，versionCode 3010000。JVM 单元测试 debug 166 项、release 163 项通过（各 2 项按设计跳过），lintVitalRelease 没有错误。真机（小米 MIX Fold 4，Android 16，无线调试）：调试版覆盖安装后 0.65 秒出画面，原有设置、服务器列表和弹幕服务都在，没有崩溃；本地夹具的设备测试（设置、弹幕、播放结束诊断、播放器反馈）通过。没有在手机上登录真实服务器或播放其中的视频，也没有在手机上看引导（测试工具会把引导关掉）。手机上的正式版保留在 3.0.0，留给发布后走一次应用内更新。
- 自动测试和试用使用隔离配置、离线夹具、本机服务和本地片段。生产服务只收到只读请求。没有连接真实的 Emby 服务器播放，也没有加入真实的一起看房间。附件哈希以发行页的 `TigerestTheater-3.1.0-SHA256SUMS.txt` 和 `RELEASE-MANIFEST.json` 为准。

## 已知问题

- Windows：VFG 只在开发机（RTX 4090）上实测，RTX 40 的其他型号和 RTX 50 系还没验证；高倍数、4K 片源和「高」档会明显增加显卡负载。
- Windows：第三方弹幕服务在真实客户端里只对本机部署的兼容服务试过，没有接入 misaka_danmu_server 或 danmu_api 的公开部署。
- Windows：RTX 超分辨率在开发机上看不出 AI 超分的效果（和 d3d11vpp 的普通放大几乎一样），可能是 NVIDIA App 里「超分辨率」的开关没开；打开后看不出变化时，请先检查 NVIDIA App 的设置。RTX Video HDR 在同一台机器上生效。
- Windows：开着 RTX 视频增强时，排在 RTX 后面的软件滤镜处理不了 RTX 输出的显存画面，mpv 会报错并关掉那个滤镜。客户端自己的 RIFE 和 VFG 总是加在 RTX 前面，不受影响；SVP 和 RTX 同时使用还没有测试，遇到 SVP 不生效时请先关闭 RTX 视频增强。
- Windows：不开补帧、使用默认的「显示器重采样」时，部分高刷新率环境下窗口播放仍可能持续卡顿、增加输出丢帧，全屏正常。遇到时请先全屏播放，见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
- Windows：RIFE 补帧时播放如果卡顿一下（例如别的程序突然占满显卡），可能把这一集误判成变帧率，状态显示「变帧率视频保持原帧播放」，这一集剩下的部分不再补帧。重新打开这一集会重新判断。
- 每帧实际时长和容器标的帧率对不上的视频不补帧，保持原帧播放。
- Windows 与 Android：服务器准备字幕超过 10 秒时，开头一段没有字幕；服务器一直不返回时字幕不会出现，也不一定有失败提示。
- 本地播放还不能把文件直接拖进已经打开的窗口（拖到程序图标或快捷方式上可以），也不记录本地文件的续播位置。
