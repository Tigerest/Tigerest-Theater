本次只发布 Windows（安装版和便携版）。Mac 仍是 2.9.5.3，安装包在 [2.9.5.3 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.5.3)；Android、iPhone／iPad 与 Apple TV 仍是 2.9.5，安装包在 [2.9.5 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.5)；这些平台的检查更新不会提示这一版。Windows 的 2.9.5 到 2.9.5.7 检查更新会提示 2.9.5.8。

这一版修的是 GitHub 上的 [#39](https://github.com/Tigerest/Tigerest-Theater/issues/39)。

## 内置播放器不响应「片头跳过模式」（#39）

- **问题：** Emby 用户设置里的「片头跳过模式」选了「自动跳过片头」或「显示跳过片头按钮」，服务器也已经检测出片头，用内置播放器播放时既不自动跳，也没有按钮；同一集在 Emby 自带的网页播放器里正常。
- **原因：** Emby 的跳过按钮和自动跳过都写在它的网页播放界面里。内置播放器播放时画面由 uosc 接管，那个网页界面不显示，这段逻辑从不执行。进度条上以蓝色标出的 `Opening` 区段来自视频文件自带的章节，不是 Emby 的片头检测结果，所以看得到区段却没有跳过。
- **修复：** 客户端读取 Emby 给这一集的片头标记（和网页播放器用的是同一份数据），交给 uosc。选「显示跳过片头按钮」时，进入片头后画面右下角、控制栏上方出现「跳过片头」按钮，点击跳到片头结束；选「自动跳过片头」时，进入片头后直接跳到片头结束，并提示「已跳过片头」。离片头结束不到 2 秒时不再显示按钮，这个余量和 Emby 的网页播放器一样。
- **条件：** 和 Emby 自带的网页播放器相同：读的是同一个「片头跳过模式」设置，服务器要在媒体库选项里启用片头检测，并且 Emby Premiere 有效。
- **一起看：** 在一起看房间里不会自动跳过，只显示按钮；房间里任何位置跳动都会同步给所有人，点了按钮会带着整个房间一起跳。
- **没有包含的：** 片尾不会自动跳过（Emby 的网页播放器对片尾标记也只是提前弹出「下一集」）。Jellyfin 服务器的片头跳过还没有做。服务器转码、并且是从中途开始的非 HLS 串流不处理片头。Mac 版的改动在同一份代码里，要等下一个 Mac 安装包。
- **没有验证的：** 这一版没有连着真实的 Emby 服务器播放验证过。按钮和自动跳过是在真实客户端里用本地片段测的；读取片头标记、读取「片头跳过模式」和 Emby Premiere 校验只有单元测试。升级后不生效时，请在 issue 里说明服务器版本和选的模式。

其他功能与 2.9.5.7 相同。

## 安装

- `TigerestTheater-2.9.5.8-x64.exe`：Windows 安装版；或完整解压 `TigerestTheater-2.9.5.8-x64.zip` 便携版（保留 `data`）。在 2.9.5 到 2.9.5.7 的更新窗口点「安装更新」会自动关闭、静默安装并重新打开。2.9.4 的检查更新识别不了四段版本号，会先提示 2.9.5，装好后再检查一次就能升到 2.9.5.8，也可以直接运行这一版的安装包；从 2.9.3 及更早版本升级时完全退出客户端后运行安装向导。未做 Authenticode 签名。
- 播放内核和修补版 QtWebEngine 与 2.9.5.1 到 2.9.5.7 相同。播放内核的原始构建产物 `Tigerest-mpv-rife-x64-5122104.zip` 在 [2.9.5.1 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.5.1)，修补版 QtWebEngine 的组件包见 [2.9.4 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.4)的 `TigerestWebEngine-6.9.3-d3d11.zip`。已安装的 Windows RIFE 扩展可以继续用于 2.9.5.8，不用重新下载。
- `TigerestTheater-2.9.5.8-SHA256SUMS.txt` 校验本页全部文件；`RELEASE-MANIFEST.json` 记录来源提交、内核来源和验证范围。源码：`client-Sources.zip`（全部客户端，标签 `v2.9.5.8` 对应的提交；Windows 安装包从其中的 `32acb10` 构建，之后的提交只改文档）。
- 无法访问 GitHub 时，可从[夸克网盘](https://pan.quark.cn/s/88e6f7a795b4)或[百度网盘](https://pan.baidu.com/s/58azzOU4piiB3miyZqA1dig)的 `2.9.5` 文件夹下载同样的 Windows 安装包（文件名带 2.9.5.8），用其中的 `TigerestTheater-2.9.5.8-SHA256SUMS.txt` 校验。更新窗口的网盘按钮会打开分享首页，再依次点开 `Tigerest-Theater` 和 `2.9.5`。

## 验证范围

- **发布构建：** 安装包和便携包从 `32acb10`（打开检查更新）构建。完整串行 CTest 127 个目标全部通过（分两段运行，共 653 秒）；`test_window_chrome` 单独运行 7 项通过、0 项跳过。
- **片头跳过：** `test_emby_uosc_playlist` 把真实的 uosc 脚本装进 libmpv 播放一段生成的视频：进入片头后出现按钮、位置不动，触发后落在片头结束处；离结束 2 秒内（跳过之后是 5 秒内）不再出现；自动模式进入片头就跳到结束处，不出现按钮；换片会清掉上一集的片头。`test_player_lifecycle` 用桩对象覆盖网页一侧：按 Emby 的方式读取片头标记，三种模式，没有 Emby Premiere、没有标记、转码有偏移、一起看房间里各自的处理。`test_intro_skip_webengine` 在真实客户端里播放本地片段，见下面的便携包试用。
- **安装包：** 便携包 1534 个文件与暂存目录逐字节一致，OpenSSL、播放内核（两个 DLL 角色是同一份）与修补版 QtWebEngine 的哈希与锁定值一致。和 2.9.5.7 的便携包逐文件比较：文件数相同，只有主程序 `Tigerest Theater.exe` 不同（uosc 的脚本打包在主程序里）。主程序版本 2.9.5.8，构建号 `32acb10c`，构建日期 2026-11-13。
- **便携包试用：** 便携包解压到新文件夹，在没有开发环境的命令行里用独立配置运行，没有登录任何账号。`tests/test_intro_skip.cjs` 播放一段本地片段，片头标记设为 3–30 秒：按钮在 3.04 秒出现，不点不会自己跳；暂停在 4.75 秒时触发跳过，落在 30.00 秒；自动模式下播放到片头就跳到 30.04 秒，不出现按钮。窗口截图里按钮在右下角、控制栏上方。同一份代码的开发构建上还用真实鼠标点过按钮（4.5 秒跳到 30.0 秒）。
- 自动测试和便携包试用使用隔离配置、离线夹具、本机服务和本地片段。生产服务只收到只读请求（检查更新）。没有连接真实的 Emby 服务器播放带片头标记的剧集。附件哈希以发行页的 `TigerestTheater-2.9.5.8-SHA256SUMS.txt` 和 `RELEASE-MANIFEST.json` 为准。

## 已知问题

- Windows：片头跳过没有连着真实的 Emby 服务器验证，见上文。
- Windows：IPv6 连不通时改用 IPv4（2.9.5.7）没有在这样的网络上实测。
- Windows：音画不同步的自动处理只在开发机上模拟验证过；每次打开客户端后的第一个视频仍可能先偏差几秒再切换。升级后仍然不同步、又没有看到「已改为跟随音频时钟」的提示时，请在不同步时用「故障报告」上传诊断日志。
- Windows：服务器准备字幕超过 10 秒时，开头一段没有字幕；服务器一直不返回时字幕不会出现，也不一定有失败提示。
- Windows：不开补帧、使用默认的「显示器重采样」时，部分高刷新率环境下窗口播放仍可能持续卡顿、增加输出丢帧，全屏正常。这个问题仍未修复；遇到时请先全屏播放，见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
- Windows：窗口播放剩下的抖动主要来自系统合成，和桌面活动有关（例如任务栏时钟显示秒数时，桌面每秒重绘一次）；全屏最平滑。
- Windows：全屏开着弹幕、按音频时钟播放时，10 分钟测试里出现过一次约 0.15 秒不出新画面（随后掉 2 帧），卡在处理弹幕图层的阶段，原因还没查清。
- Windows：2.9.5.1 的高刷新率节奏改进只在一台 4K 240 Hz 显示器和 RTX 4090 上实测，其他刷新率、显示器和显卡还没验证；也还没在 Emby 串流和网页界面下测过节奏。
- 每帧实际时长和容器标的帧率对不上的视频不补帧，保持原帧播放。目前补帧用的是容器标的平均帧率，帧率判定方式还没改。
- 本地播放还不能把文件直接拖进已经打开的窗口（拖到程序图标或快捷方式上可以），也不记录本地文件的续播位置。
- 返回一面这次还没显示过、图片也不在缓存里的海报墙时，服务器要 0.5–0.8 秒才给出目标卡片，转场约在 0.8–0.9 秒结束。
