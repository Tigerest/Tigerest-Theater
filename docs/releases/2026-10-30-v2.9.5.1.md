# Tigerest Theater 2.9.5.1 · 高刷新率播放与字幕字体（Windows）

本次只发布 Windows（安装版和便携版）。Android、Mac、iPhone／iPad 与 Apple TV 仍是 2.9.5，安装包在 [2.9.5 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.5)；这些平台的检查更新不会提示这一版。Windows 2.9.5 的检查更新会提示 2.9.5.1。

## 高刷新率屏幕上的播放节奏（Windows）

- **问题：** 在 240 Hz 屏幕上，59.94 帧的视频每帧应该正好停留 4 次刷新。按音频时钟播放时（2.9.5 的 RIFE 补帧在全屏和窗口都用音频时钟），mpv 翻页不对齐屏幕刷新，翻页时刻贴近刷新时，画面在相邻两次刷新之间来回摆动，停留变成 3 次、5 次交替，看起来一顿一顿的，移动的弹幕最明显。
- **修复：** 播放内核（libmpv）加了一个 Windows 翻页补丁：精确等到翻页时刻，再把每一帧对准屏幕刷新提交。窗口播放时画面由系统（DWM）合成，内核会看每一帧实际在哪次刷新显示，自动在两个提交位置之间选择更稳的一个。测到的刷新周期和标称值相差 5% 以上时（例如可变刷新率 G-SYNC／FreeSync 生效时）不做对齐，按原来的方式播放。
- **实测**（本机 4K 240 Hz 显示器、RTX 4090；1080p 23.976 帧的片子由 RIFE 4.25 补到 59.94 帧，开着弹幕，按音频时钟播放；「3/5 次交替」按每分钟出现多少对计算，越少越平滑）：改前每分钟 316–343 对。改后全屏 7.5–9.5 对，晚一次刷新才显示的帧从约 18% 降到 0；窗口 18.5–47.5 对（窗口受系统合成影响，不同时段能差一倍以上），晚到的帧从 7–9% 降到 0.4–1.1%。所有测试都没有掉帧。
- 不补帧但在设置里把音画同步选成「音频」时，同样按刷新对齐，窗口和全屏都更平滑。默认的「显示器重采样」不受这项改动影响。

## 全屏补帧时弹幕跟随屏幕刷新率（Windows）

- 2.9.5 的 RIFE 补帧在全屏和窗口都改用音频时钟，弹幕只能跟着约 60 帧的画面移动。2.9.5.1 全屏播放时保留设置里的「显示器重采样」，弹幕每次屏幕刷新都移动（240 Hz 屏幕上每秒 240 次）。窗口播放仍用音频时钟：窗口由系统合成，显示器重采样在合成下会掉帧。
- 全屏时偶尔仍会被系统合成（例如有置顶的小窗口盖在视频上），显示器重采样这时可能接连掉帧。客户端发现持续错时后把这一集自动改回音频时钟，不弹性能提示；下一集再试显示器重采样。实测一次置顶窗口盖上后约 7 秒切换，切换前掉了 23 帧，之后不再掉帧；另两次同样盖上小窗，24 秒里只掉了 2 帧和 4 帧，没到切换条件，继续用显示器重采样。
- 补帧播放暂停 5 秒以上再继续时，客户端先重新准备当前画面再继续，期间显示缓冲，大约等 1–3 秒。以前恢复时画面会落后 70–150 ms、掉 9–24 帧；实测 6 次暂停 20 秒后恢复都没有掉帧。

## 弹幕与刷新率（Windows）

- 音频时钟下（窗口补帧，或音画同步选了「音频」），弹幕改为跟着每一帧画面绘制，不再每 16.7 秒顿一下或一下跳两步。
- 显示器重采样改用系统报告的精确刷新率（例如 59.94 Hz，不再取整成 59 Hz），开始播放时音频速度不会被取整误差带偏。

## 字幕字体（Windows）

- 默认字幕字体从 Segoe UI 改为微软雅黑粗体。Segoe UI 没有中文字形，中文要逐字回退到别的系统字体，同一行里有的字是日文字体、有的是繁体字体，粗细不一（例如「难」「骗」明显比旁边的字细）。微软雅黑的中文字形完整，西文与 Segoe UI 是同一套设计。
- 字幕设置新增「字幕粗体」，默认开启，只作用于 SRT 等纯文本字幕；ASS 字幕仍按字幕脚本自带的字体和样式显示。
- 升级后，字幕字体还是原来默认的 Segoe UI 的，会自动换成微软雅黑一次；自己选过别的字体的不变，以后再改回 Segoe UI 也会保留。弹幕也改用微软雅黑。
- mpv.conf 编辑器里自己写的字幕设置照常生效。

## 安装

- `TigerestTheater-2.9.5.1-x64.exe`：Windows 安装版；或完整解压 `TigerestTheater-2.9.5.1-x64.zip` 便携版（保留 `data`）。在 2.9.5 的更新窗口点「安装更新」会自动关闭、静默安装并重新打开。2.9.4 的检查更新识别不了四段版本号，会先提示 2.9.5，装好后再检查一次就能升到 2.9.5.1，也可以直接运行这一版的安装包；从 2.9.3 及更早版本升级时完全退出客户端后运行安装向导。未做 Authenticode 签名。
- `TigerestTheater-2.9.5.1-SHA256SUMS.txt` 校验本页全部文件；`RELEASE-MANIFEST.json` 记录来源提交、内核来源和验证范围。源码：`client-Sources.zip`（全部客户端）。`Tigerest-mpv-rife-x64-5122104.zip` 是这一版使用的播放内核原始构建产物（GitHub Actions 构建，内含源码锁和补丁校验值），打包时按 `dev/windows/rife/mpv-runtime-lock.json` 核对。
- 本版使用的修补版 QtWebEngine 与 2.9.4、2.9.5 相同，组件包见 [2.9.4 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.4)的 `TigerestWebEngine-6.9.3-d3d11.zip`。
- 已安装的 Windows RIFE 扩展可以继续用于 2.9.5.1，不用重新下载。
- 无法访问 GitHub 时，可从[夸克网盘](https://pan.quark.cn/s/88e6f7a795b4)或[百度网盘](https://pan.baidu.com/s/58azzOU4piiB3miyZqA1dig)的 `2.9.5.1` 文件夹下载同样的 Windows 安装包，用 `SHA256SUMS.txt` 校验。

## 验证范围

- **Windows 发布构建：** 安装包和便携包从 `6e717e8` 构建（打开检查更新，播放内核按 `mpv-runtime-lock.json` 取自 GitHub Actions 构建 40937947776）；之后的提交只改文档和两个测试，测试不进安装包。完整串行 CTest 122 个目标中 120 个首轮通过（562 秒）。另外两个是测试自身的问题：`test_rife_extension_package` 拿四段版本号 2.9.5.1 去查 RIFE 扩展目录，而客户端查目录用的是三段的 2.9.5，改成按三段查后通过；`test_server_onboarding_webengine` 连续两次在「切换服务器」时失败——切换会换掉页面和它的渲染进程，正赶上的 DevTools 请求被丢弃，测试没有重试（不改代码重跑 7 次都通过）。两个测试修正后在 CTest 里各连跑 10 次通过。`test_window_chrome` 的 7 个用例全部执行，没有跳过；默认关闭的联网用例没有开启。
- **播放内核：** 新内核按 `dev/windows/rife/README.md` 的流程验收：真实 EOF／色彩和 tiny TensorRT 流式测试连续 10 轮通过，Player 生命周期、mpv 早／晚激活、VSScript 与 TensorRT 帧图测试通过；1080p 23.976 帧真实片源，三个模型各在默认 4K 输出下播放 600 秒（2.5×、音频时钟、默认 3 个着色器），全程补帧、0 掉帧、音画偏差最大 0.13 ms。CTest 里的 `test_rife_mpv_build` 用钉住的 mpv 源码编译并检查翻页补丁的等待、刷新对齐和合成提交位置选择。
- **Windows 安装包：** 便携包 1534 个文件与暂存目录逐字节一致，OpenSSL、新内核（两个 DLL 角色是同一份）与修补版 QtWebEngine 的哈希与锁定值一致。解压到空目录、只保留系统目录 PATH，用本地测试视频启动：Qt、WebEngine 与 mpv 都从包内加载，D3D11 fence 同步就绪，画面和同名外挂字幕正常，87 个内置着色器为 LF 换行；字幕字体为微软雅黑粗体（libass 选中 MicrosoftYaHei-Bold）。更新窗口显示「当前版本 2.9.5.1」和「构建号 6e717e8a · 2026-10-30」，在线检查结果为当前平台没有更新的正式版。便携包装上 RIFE 扩展后播放真实片源：1.1 秒进入补帧（TensorRT、rife-4.25、23.976→59.94 帧），随后 10 秒补出 483 帧，没有性能提示。
- **节奏与回退：** 上面的实测都在本机 4K 240 Hz 显示器和 RTX 4090 上，用隔离配置、本地片源和空白或夹具页面，没有经过 Emby 串流和网页界面。全屏 7.5–9.5 对是第一版翻页补丁的本地构建测的，这一版内核全屏直通的翻页时序与它相同，没有再测；窗口 18.5–26.5 对是这一版内核，44.0–47.5 对是第一版补丁。全屏合成回退和补帧暂停恢复是在换内核之前测的，换内核后没有重测。
- 网页测试均使用隔离配置和离线夹具；生产接口只收到只读的检查更新请求，没有用真实 Emby 账号登录。附件哈希以发行页的 `TigerestTheater-2.9.5.1-SHA256SUMS.txt` 和 `RELEASE-MANIFEST.json` 为准。

## 已知问题

- 不开补帧、使用默认的「显示器重采样」时，部分 Windows 高刷新率环境下窗口播放仍可能持续卡顿、增加输出丢帧，全屏正常。这一版的翻页对齐只作用于音频时钟，不改变显示器重采样，这个问题仍未修复；遇到时请先全屏播放，见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
- 窗口播放剩下的抖动主要来自系统合成，和桌面活动有关（例如任务栏时钟显示秒数时，桌面每秒重绘一次）；全屏最平滑。
- 全屏开着弹幕、按音频时钟播放时，10 分钟测试里出现过一次约 0.15 秒不出新画面（随后掉 2 帧），卡在处理弹幕图层的阶段，与这次改动无关，原因还没查清。
- 以上节奏改进只在一台 4K 240 Hz 显示器和 RTX 4090 上实测，其他刷新率、显示器和显卡还没验证；也还没在 Emby 串流和网页界面下测过节奏。
- 本地播放还不能把文件直接拖进已经打开的窗口（拖到程序图标或快捷方式上可以），也不记录本地文件的续播位置。
- 返回一面这次还没显示过、图片也不在缓存里的海报墙时，服务器要 0.5–0.8 秒才给出目标卡片，转场约在 0.8–0.9 秒结束。
