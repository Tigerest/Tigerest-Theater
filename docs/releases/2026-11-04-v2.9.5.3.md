# Tigerest Theater 2.9.5.3 · 补帧闪退与鼠标自动隐藏（Mac）

本次只发布 Mac。Windows 仍是 2.9.5.2，安装包在 [2.9.5.2 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.5.2)；Windows 版 2.9.5.3 还没有打包，Windows 的检查更新不会提示这一版。Android、iPhone／iPad 与 Apple TV 仍是 2.9.5，安装包在 [2.9.5 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.5)。Mac 的 2.9.5、2.9.5.1 和 2.9.5.2 检查更新会提示 2.9.5.3。

## 开着补帧播放部分视频时闪退（Mac）

- **问题：** 开着 RIFE 补帧，播放部分视频时一开始播放客户端就闪退。帧率带零头的视频会触发，例如容器标的是 23.9988 帧；23.976、24、25 这些常见帧率不受影响。补帧插件把帧率翻倍后没有约分（23.9988 帧记作 59997/2500，翻倍后是 119994/2500），VapourSynth 拒绝创建补帧滤镜；插件在这条失败路径上又没有释放输入画面，播放内核清理滤镜时检查到输入还在被引用，直接退出。
- **修复：** 输出帧率先约分再交给 VapourSynth，这类视频可以正常创建补帧滤镜。补帧滤镜以后再因为别的原因创建失败，插件也会释放输入画面，结果只是这一集不补帧，不会闪退。
- 每帧实际时长和容器标的帧率对不上的视频（例如容器标 23.9988 帧、实际每帧 40 毫秒）仍会提示「变帧率视频保持原帧播放」，不补帧。

## 播放窗口的鼠标自动隐藏（Mac）

- **问题：** Mac 的播放窗口里，鼠标停住不动也一直显示，不会自动隐藏。
- **原因：** 客户端给 mpv 注册的快捷键（F11、Ctrl+J、ESC 停止、关闭窗口停止等）放在一个单独的按键区段里，启用时没有声明这个区段不需要鼠标。mpv 因此一直认为鼠标在被使用，不隐藏光标。Mac 的播放窗口靠 mpv 自己隐藏光标，所以一直受影响；Windows 由客户端自己隐藏鼠标，不受影响。
- **修复：** 两个只有快捷键的区段（包括补帧启动等待时用的那个）都声明不需要鼠标。鼠标停住后，按 mpv.conf 里的 `cursor-autohide`（默认 0.8 秒）自动隐藏；移到底部进度条等控件上时照常显示。

## 同时带上的修复

下面这些改动已经在代码里，这次随 Mac 版一起发布；标着 Windows 的部分要等 Windows 版 2.9.5.3 打包后才会到 Windows 用户手上。

- **播放启动（Windows、Mac）：** 网速慢、缓存还在加载时，不再在 30 秒时报「播放器启动超时（30 秒）」并停止播放；缓存在 10 秒内有增长就继续等，长时间不涨才报超时。
- **外挂字幕和音轨（Windows、Mac）：** 选用 Emby 的外挂字幕（例如服务器要从视频里现提取的字幕）时，窗口不再卡住；字幕在后台加载，视频仍等选中的字幕加载好再开始。外挂音轨同样处理。
- **画质档位（Windows、Mac）：** 切换画质档位时窗口不再卡住，各项设置按顺序在后台生效。着色器重新编译期间，画面和 mpv 菜单仍可能顿一下。
- **诊断报告（Windows）：** 日志里的中文不再是乱码。

## 安装

- `TigerestTheater-2.9.5.3-arm64.dmg`：Apple Silicon Mac，macOS 26+。打开后把应用拖入「应用程序」替换旧版；Mac 2.9.5、2.9.5.1 和 2.9.5.2 的更新窗口会找到这个文件。Mac 2.9.4 的检查更新识别不了四段版本号，会先提示 2.9.5，装好后再检查一次就能升到 2.9.5.3。使用 ad-hoc 签名，未经 Apple 公证。
- 播放内核（libmpv）、修补版 QtWebEngine、Python 与 VapourSynth 运行库和 2.9.5.2 相同；补帧插件 `tigerest-rife-vs.dylib` 换成了修好的版本。
- `TigerestTheater-2.9.5.3-SHA256SUMS.txt` 校验本页全部文件；`RELEASE-MANIFEST.json` 记录来源提交和验证范围。源码：`client-Sources.zip`（全部客户端，本版的发布提交；Mac 的构建提交包含在内，之后的提交只改文档）。
- Windows 请继续使用 2.9.5.2。

## 验证范围

- **Mac 发布构建：** DMG 在 Mac 上从 `696ba69` 构建（之后的提交只改文档），用 Xcode 27.2 SDK 编译，QtWebEngine 是修补版（UUID `76AE7891-C29A-31D6-815F-C1505E445F07`），`codesign --verify --deep --strict` 通过。完整串行 CTest 94 个目标中 93 个通过（331 秒）；没通过的 `test_mpvconf_editor_webengine`（237 对 238 行）是 Mac 上已知的失败，原因见已知问题里 SVP 那一条。
- **补帧插件：** 用 VapourSynth R79 直接调用插件：2.9.5.2 的插件在 59997/2500 和 1199/50 两种帧率下都报出同样的错误，而且失败后不释放输入画面；新插件输出 59997/1250 和 1199/25，失败路径上的输入画面也能释放。插件测试新增偶数分母帧率的用例，在旧插件上失败、新插件上通过。用真实的 mpv 播放一段 23.9988 帧的测试视频：旧插件下 mpv 在 `destroy_vs` 的 `in_node_active` 断言处退出（SIGABRT），和用户的两份崩溃报告一致；新插件正常补帧，输出帧时长总和准确。这个用例已加进流式补帧测试。
- **鼠标：** 在隔离配置里播放本地测试视频，注入记录工具跟踪 mpv 隐藏光标的调用。修复前 mpv 的播放窗口是活动窗口、鼠标在窗口里，mpv 也从不隐藏光标；修复后用 mpv 的 `mouse` 命令把鼠标移到画面中央和顶部，约 0.8 秒后光标隐藏，移到底部进度条上一直显示。测试里的鼠标移动是用 mpv 命令模拟的，真实鼠标操作由用户在测试包里试过。
- **真实播放：** 用户在 Mac 上装了 2.9.5.3 的第一版测试包（还没有鼠标修复），播放之前闪退的那一集 3 次，不再闪退；这一集每帧 40 毫秒、容器标 23.9988 帧，补帧判定为变帧率，保持原帧播放。最终测试包由用户试用后确认。
- **DMG 对比：** 和 2.9.5.2 的 DMG 逐文件比较，都是 2588 个文件；不同的是主程序、补帧插件 `tigerest-rife-vs.dylib`、Info.plist（版本 2.9.5.3）、构建记录、签名清单，以及打包时重新编译的 RIFE Core ML 模型描述（模型权重不变）。播放内核、Python、VapourSynth 和 QtWebEngine 逐字节相同。
- 测试使用隔离配置、离线夹具和本地生成的测试视频，没有用真实 Emby 账号登录；用户自己的试播除外。附件哈希以发行页的 `TigerestTheater-2.9.5.3-SHA256SUMS.txt` 和 `RELEASE-MANIFEST.json` 为准。

## 已知问题

- 每帧实际时长和容器标的帧率对不上的视频不补帧，保持原帧播放。目前补帧用的是容器标的平均帧率，帧率判定方式还没改。
- Mac：本次运行中开始播放过以后，在设置里保存 mpv.conf 会丢掉 SVP 的连接设置，SVP 要到下次打开客户端才能重新连上。2.9.4 起就有这个问题，2.9.5.3 仍未修复。
- 本地播放还不能把文件直接拖进已经打开的窗口（拖到程序图标上可以），也不记录本地文件的续播位置。
- 返回一面这次还没显示过、图片也不在缓存里的海报墙时，服务器要 0.5–0.8 秒才给出目标卡片，转场约在 0.8–0.9 秒结束。
