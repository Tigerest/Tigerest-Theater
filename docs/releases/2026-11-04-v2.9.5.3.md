# Tigerest Theater 2.9.5.3 · 补帧闪退、窗口卡住与启动超时（Windows、Mac）

| 平台 | 安装包 | 系统要求 |
| --- | --- | --- |
| Windows 安装版 | [2.9.5.3 EXE][dl-win-exe] | Windows 10 1903+ / Windows 11，x64 |
| Windows 便携版 | [2.9.5.3 ZIP][dl-win-zip] | 同上；完整解压后运行 |
| Apple Silicon Mac | [2.9.5.3 DMG][dl-mac] | macOS 26+，M 系列芯片 |

本次发布 Mac 与 Windows（安装版和便携版）。Mac 版先发布，Windows 版随后加入同一个发行页。Android、iPhone／iPad 与 Apple TV 仍是 2.9.5，安装包在 [2.9.5 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.5)；这些平台的检查更新不会提示这一版。Windows 与 Mac 的 2.9.5、2.9.5.1 和 2.9.5.2 检查更新会提示 2.9.5.3。

## 开着补帧播放部分视频时闪退（Mac）

- **问题：** 开着 RIFE 补帧，播放部分视频时一开始播放客户端就闪退。帧率带零头的视频会触发，例如容器标的是 23.9988 帧；23.976、24、25 这些常见帧率不受影响。补帧插件把帧率翻倍后没有约分（23.9988 帧记作 59997/2500，翻倍后是 119994/2500），VapourSynth 拒绝创建补帧滤镜；插件在这条失败路径上又没有释放输入画面，播放内核清理滤镜时检查到输入还在被引用，直接退出。
- **修复：** 输出帧率先约分再交给 VapourSynth，这类视频可以正常创建补帧滤镜。补帧滤镜以后再因为别的原因创建失败，插件也会释放输入画面，结果只是这一集不补帧，不会闪退。
- 每帧实际时长和容器标的帧率对不上的视频（例如容器标 23.9988 帧、实际每帧 40 毫秒）仍会提示「变帧率视频保持原帧播放」，不补帧。

## 播放窗口的鼠标自动隐藏（Mac）

- **问题：** Mac 的播放窗口里，鼠标停住不动也一直显示，不会自动隐藏。
- **原因：** 客户端给 mpv 注册的快捷键（F11、Ctrl+J、ESC 停止、关闭窗口停止等）放在一个单独的按键区段里，启用时没有声明这个区段不需要鼠标。mpv 因此一直认为鼠标在被使用，不隐藏光标。Mac 的播放窗口靠 mpv 自己隐藏光标，所以一直受影响；Windows 由客户端自己隐藏鼠标，不受影响。
- **修复：** 两个只有快捷键的区段（包括补帧启动等待时用的那个）都声明不需要鼠标。鼠标停住后，按 mpv.conf 里的 `cursor-autohide`（默认 0.8 秒）自动隐藏；移到底部进度条等控件上时照常显示。

下面四个问题都来自用户发来的故障诊断报告。

## 缓存还在加载时被判为启动超时（Windows、Mac）

- **问题：** 开始播放满 30 秒时，播放器会报「播放器启动超时（30 秒）」并停止，即使画面已经出来、缓存正在往上涨。网速慢或服务器转码慢时容易遇到；有一份报告里停止时缓存已经到 48%，还在增长。
- **修复：** 缓存在 10 秒内有增长就继续等；缓存长时间不涨才报超时，总等待时间仍有上限。

## 外挂字幕和音轨卡住窗口（Windows、Mac）

- **问题：** 选用 Emby 的外挂字幕（例如服务器要从视频里现提取的字幕）时，播放器要等服务器把字幕传回来窗口才响应。服务器慢时整个窗口冻住，报告里有一次 8 秒。
- **修复：** 字幕在后台加载，窗口照常响应。视频仍然等选中的字幕加载好再开始，开头不会缺字幕。加载期间换了别的字幕或关掉字幕，迟到的那一条不会把选择改回去。外挂音轨同样处理。

## 切换画质档位卡住窗口（Windows、Mac）

- **问题：** 切换画质档位时，档位里每一项设置都要等视频输出重新编译着色器。暂停时切换最明显，报告里有一次窗口冻住 5.6 秒。
- **修复：** 档位里的各项设置按顺序在后台生效，窗口照常响应；有设置不被接受时照旧提示。着色器重新编译期间，画面和 mpv 菜单仍可能顿一下。

## 诊断报告里的中文是乱码（Windows）

- **问题：** 日志里的中文（报错信息、文件路径、片名等）在诊断报告里变成乱码，服务器管理员看不出报错内容。
- **修复：** 这些日志按 UTF-8 写入，中文原样保留。

其他功能与 2.9.5.2 相同。

- Windows：播放内核和修补版 QtWebEngine 与 2.9.5.1、2.9.5.2 相同；随包的补帧插件同样带上了「补帧滤镜创建失败时释放输入画面」的修复。播放内核的原始构建产物 `Tigerest-mpv-rife-x64-5122104.zip` 在 [2.9.5.1 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.5.1)，修补版 QtWebEngine 的组件包见 [2.9.4 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.4)的 `TigerestWebEngine-6.9.3-d3d11.zip`。已安装的 Windows RIFE 扩展可以继续用于 2.9.5.3，不用重新下载。

## 验证范围

- **Windows 发布构建：** 安装包和便携包从 `ecfeb68`（打开检查更新）构建，和 Mac 版是同一个发布提交。完整串行 CTest 123 个目标全部通过（563 秒）。新加的 `test_player_async_mpv` 用本机的慢速字幕服务（1.5 秒才回应）和生成的视频播放：界面线程最长停顿不到 0.7 秒；选中的字幕加载好以前不开始播放；加载期间改选「无字幕」，迟到的字幕不会被选中。把字幕加载临时改回旧的同步写法时，这个测试测到界面卡住 1517 ms 而失败。同一测试还检查画质档位的设置按顺序排队、连切两个档位时以后一个为准、不被接受的设置会提示，以及 mpv 日志里的中文完整。启动超时的测试模拟缓存 0%、3%、48% 地增长，旧代码会在 30 秒时停止播放；新代码继续等，缓存停止增长以后才判超时。
- **Windows 安装包：** 便携包 1534 个文件与暂存目录逐字节一致，OpenSSL、播放内核（两个 DLL 角色是同一份）与修补版 QtWebEngine 的哈希与锁定值一致；和 2.9.5.2 的便携包逐文件比较，只有主程序和补帧插件 `rife/tigerest-rife-vs.dll` 不同。程序内的构建号为 `ecfeb685`，构建日期 2026-11-04。发行页上的 `client-Sources.zip` 与 `ecfeb68` 的文件逐一相同（Windows 换行的文件按换行归一后比较）。
- **Windows 实机检查：** 便携包解压到新文件夹，用独立配置打开一段本机生成的 1080p 视频（文件名含中文，带同名字幕），正常开始播放。播放中加一条 2.5 秒才回应的外挂字幕，字幕加载后被选中，期间对界面线程的调用最慢 17–20 ms；同样的操作在 2.9.5.2 上卡住约 2.5 秒（2506–2510 ms）。暂停时依次切换 4 个画质档位，最慢 48 ms（2.9.5.2 为 94 ms）：这台电脑（RTX 4090）上切换档位本来就不慢，报告里 5.6 秒的卡顿没有复现，这一项只由上面的测试覆盖。日志里 2.9.5.2 有 354 个乱码字符，中文文件名无法辨认；2.9.5.3 没有乱码。缓存慢慢增长的启动过程没有在实机上复现，这一项也只由测试覆盖。Mac 的鼠标修复 Windows 也会编译进去：用程序把鼠标移到播放窗口中央，2.9.5.2 和 2.9.5.3 都是停住约 3 秒后隐藏、移动后出现、再停住又隐藏，行为一致。
- **Mac 发布构建：** DMG 在 Mac 上从 `696ba69` 构建（之后的提交只改文档），用 Xcode 27.2 SDK 编译，QtWebEngine 是修补版（UUID `76AE7891-C29A-31D6-815F-C1505E445F07`），`codesign --verify --deep --strict` 通过。完整串行 CTest 94 个目标中 93 个通过（331 秒）；没通过的 `test_mpvconf_editor_webengine`（237 对 238 行）是 Mac 上已知的失败，原因见已知问题里 SVP 那一条。
- **补帧插件（Mac）：** 用 VapourSynth R79 直接调用插件：2.9.5.2 的插件在 59997/2500 和 1199/50 两种帧率下都报出同样的错误，而且失败后不释放输入画面；新插件输出 59997/1250 和 1199/25，失败路径上的输入画面也能释放。插件测试新增偶数分母帧率的用例，在旧插件上失败、新插件上通过。用真实的 mpv 播放一段 23.9988 帧的测试视频：旧插件下 mpv 在 `destroy_vs` 的 `in_node_active` 断言处退出（SIGABRT），和用户的两份崩溃报告一致；新插件正常补帧，输出帧时长总和准确。这个用例已加进流式补帧测试。
- **鼠标（Mac）：** 在隔离配置里播放本地测试视频，注入记录工具跟踪 mpv 隐藏光标的调用。修复前 mpv 的播放窗口是活动窗口、鼠标在窗口里，mpv 也从不隐藏光标；修复后用 mpv 的 `mouse` 命令把鼠标移到画面中央和顶部，约 0.8 秒后光标隐藏，移到底部进度条上一直显示。测试里的鼠标移动是用 mpv 命令模拟的，真实鼠标操作由用户在测试包里试过。
- **Mac 真实播放：** 用户在 Mac 上装了 2.9.5.3 的第一版测试包（还没有鼠标修复），播放之前闪退的那一集 3 次，不再闪退；这一集每帧 40 毫秒、容器标 23.9988 帧，补帧判定为变帧率，保持原帧播放。最终测试包由用户试用后确认。
- **DMG 对比：** 和 2.9.5.2 的 DMG 逐文件比较，都是 2588 个文件；不同的是主程序、补帧插件 `tigerest-rife-vs.dylib`、Info.plist（版本 2.9.5.3）、构建记录、签名清单，以及打包时重新编译的 RIFE Core ML 模型描述（模型权重不变）。播放内核、Python、VapourSynth 和 QtWebEngine 逐字节相同。
- 测试和 Windows 实机检查使用隔离配置、离线夹具和本地生成的测试视频，Windows 实机检查关闭了自动故障报告；没有用真实 Emby 账号登录，Windows 上也没有在 Emby 服务器上实际播放，外挂字幕和启动超时只用本机服务和夹具验证。生产接口只收到只读的检查更新请求；用户自己在 Mac 上的试播除外。附件哈希以发行页的 `TigerestTheater-2.9.5.3-SHA256SUMS.txt` 和 `RELEASE-MANIFEST.json` 为准。

## 已知问题

- 每帧实际时长和容器标的帧率对不上的视频不补帧，保持原帧播放。目前补帧用的是容器标的平均帧率，帧率判定方式还没改。
- Windows：不开补帧、使用默认的「显示器重采样」时，部分高刷新率环境下窗口播放仍可能持续卡顿、增加输出丢帧，全屏正常。这个问题仍未修复；遇到时请先全屏播放，见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
- Windows：窗口播放剩下的抖动主要来自系统合成，和桌面活动有关（例如任务栏时钟显示秒数时，桌面每秒重绘一次）；全屏最平滑。
- Windows：全屏开着弹幕、按音频时钟播放时，10 分钟测试里出现过一次约 0.15 秒不出新画面（随后掉 2 帧），卡在处理弹幕图层的阶段，原因还没查清。
- Windows：2.9.5.1 的高刷新率节奏改进只在一台 4K 240 Hz 显示器和 RTX 4090 上实测，其他刷新率、显示器和显卡还没验证；也还没在 Emby 串流和网页界面下测过节奏。
- Mac：本次运行中开始播放过以后，在设置里保存 mpv.conf 会丢掉 SVP 的连接设置，SVP 要到下次打开客户端才能重新连上。2.9.4 起就有这个问题，2.9.5.3 仍未修复。
- 本地播放还不能把文件直接拖进已经打开的窗口（拖到程序图标或快捷方式上可以），也不记录本地文件的续播位置。
- 返回一面这次还没显示过、图片也不在缓存里的海报墙时，服务器要 0.5–0.8 秒才给出目标卡片，转场约在 0.8–0.9 秒结束。
