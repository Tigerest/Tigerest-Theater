## 专业模式（Windows）

- **进入和退出：** 播放时按 `F2`，或点 uosc 控制栏里的仪表盘按钮；再按 `F2` 或点右上角「退出专业模式」回到普通播放。画面缩到左边继续播放，右边是调节面板，下方是实时统计。
- **七页面板：** 「画质」页列出处理顺序（从输入、解码、滤镜、着色器、缩放到输出的每一步）、画质档位、着色器链（可以临时卸下某一个、调整顺序或挂载新的）、缩放、NVIDIA RTX 视频增强、去色带与抖动；「补帧」页是 RIFE、NVIDIA VFG 和 mpv 时间插帧；「色彩」页是亮度、对比度等画面调整和 HDR 与色彩管理；「声音」「字幕」「弹幕」「画面」页分别是音量与延迟、字幕字体和位置、弹幕样式、同步模式与缩放平移。改动立即作用到画面。
- **对比：** 按住「按住对比改动前」看改动之前的画面；按住「按住看原始画面」看关掉所有着色器、去色带和画面调整，只用双线性缩放的画面（色彩管理保持不变）。松开恢复，暂停时也能对比。
- **统计：** 信号一栏列出输入、解码、画面、色彩、显示、同步、缓存和音频；GPU 渲染耗时按阶段列出，并和每帧的时间预算比较；视频帧率和屏幕实际呈现的帧率各有一条曲线；补帧、渲染、呈现、GPU 与 CPU 占用和丢帧画成负载环，用来找丢帧出在哪一步。
- **保存：** 「保存」把画质参数和着色器链写回当前档位；「保存为新档位…」另存一个继承当前档位的新档位，自己建的档位可以删除。同步模式、字幕字体／粗体／大小／垂直位置、显示器 ICC、VFG 和 RTX 写回「设置」里对应的项；弹幕样式的改动直接保存到「设置 → 弹幕样式」。「复制为 mpv.conf」导出改动的配置行，「重置改动」回到改动之前。没保存的改动只对这次播放有效。

## NVIDIA VFG 帧生成（Windows）

- RIFE 之外的另一种补帧：NVIDIA Video Frame Generation（Video Effects SDK 里的帧生成模型）。按 0.5 倍一档把帧率提高到源帧率的 1.5–5 倍，「自动」按「RIFE 目标帧率」选最接近的一档（23.976 fps、目标 60 时是 2.5 倍）；质量分低、中、高三档，档位越高显卡开销越大。
- **条件：** RTX 40 或 RTX 50 系显卡（驱动 570.65 或更新）；已安装 Windows RIFE 扩展（VFG 借用扩展里的 VapourSynth 运行库）；硬件解码用默认的「硬解后复制回显」或软件解码。不满足时，设置说明和专业模式会写出缺的是哪一项。
- **开启：** 「设置 → 视频」的「NVIDIA 帧生成（VFG）」和「VFG 倍数」，从下一个视频起生效；播放中在专业模式的「补帧」页切换，立即生效。开启后这一集的 RIFE 让出。
- **运行库：** NVIDIA 的运行库（nvidia-vfx 0.2.0.0 里的 5 个 DLL，约 200 MB）随安装包放在安装目录的 `vfg\nvidia`，按 NVIDIA 的许可条款原样分发，许可文件和来源记录在 `licenses\nvidia-vfx`。打包时每个文件都和 NVIDIA 软件源上 nvidia-vfx 0.2.0.0 安装包里的原文件逐一核对哈希。删掉 `vfg\nvidia` 只会让 VFG 不可用，不影响其他功能。

## NVIDIA RTX 视频增强（Windows）

- 「设置 → 视频」新增「NVIDIA RTX 视频超分辨率（VSR）」和「NVIDIA RTX Video HDR」，默认关闭。播放中改动立即生效，专业模式的「画质」页也能切换。
- **超分辨率：** 由显卡驱动把视频放大到屏幕的分辨率（按画面显示的尺寸计算，最多 4 倍），代替 mpv 的放大算法，档位里的放大着色器随之不再起作用；视频不比屏幕小时不处理。
- **RTX Video HDR：** 由显卡驱动把 SDR 视频实时转换成 HDR，HDR 片源不受影响。需要屏幕开着 Windows HDR；同时开着「播放 HDR 时自动开启系统 HDR」时，从下一个视频起 SDR 视频也会自动开启系统 HDR，播放结束后恢复。
- **处理顺序：** 两项通过 mpv 的 d3d11vpp 滤镜交给驱动，始终排在所有滤镜和补帧之后，作用于补帧后的画面。播放中打开 RIFE 或 VFG 时，客户端先把 RTX 滤镜取下、加上补帧，再把 RTX 放回最后。
- **条件：** RTX 20 系或更新的显卡，并在 NVIDIA App 的「系统 → 视频 → RTX 视频增强」（或 NVIDIA 控制面板的「调整视频图像设置」）里打开「超分辨率」或「HDR」，质量档位也在那里调。没有生效时，专业模式写出原因（视频不比屏幕小、屏幕没开 HDR、片源本身就是 HDR、驱动不接受等）。

## 设置与首页（Windows）

- 「设置 → 视频」新增「显示器 ICC 色彩配置」：自动（默认）、始终使用、不使用。「自动」读取显示器的 ICC 配置文件，但系统已经在为这块屏幕管理色彩时（开着 Windows HDR 或「自动管理应用的颜色」）不读，免得校正两次。以前由画质档位里的 `icc-profile-auto` 决定，现在它只在开启「高级覆盖」时生效。
- 「设置 → 字幕」新增「字幕垂直位置」。
- 没有选定服务器时，打开后先选择使用方式：「本地播放」（本机文件、局域网共享、离线媒体）或「连接媒体服务器」（Emby／Jellyfin）。右上角固定有「设置」按钮。
- 播放时 `Ctrl+V` 能粘贴进 uosc 的输入框了（例如弹幕的「添加弹幕源」）；粘贴的文字去掉换行和首尾空格。

## 专业模式（Mac）

- **进入和退出：** 和 Windows 一样，播放时按 `F2` 或点 uosc 控制栏里的仪表盘按钮进入，再按 `F2` 或点右上角「退出专业模式」退出。窗口和全屏都能用；从全屏进入的，退出后仍是全屏。画面缩到左边继续播放，右边七页面板、下方实时统计、两种按住对比、「保存」「保存为新档位…」和「复制为 mpv.conf」都与 Windows 相同。
- **Mac 上的不同：** 没有 NVIDIA VFG 和 RTX 视频增强，这两组不显示。「补帧」页是 RIFE 的状态、系统原生补帧（见下一节，播放中切换方式和输出帧率立即生效，「保存」写回设置）和 mpv 时间插帧。负载环里的 GPU 占用读自系统的图形处理器统计，CPU 占用是整机的。
- **实现：** Mac 的视频由单独的原生窗口显示（gpu-next），专业模式把它缩到客户端窗口左边、跟着窗口移动和缩放；全屏切换时先等系统的全屏动画结束再摆放，免得画面错位。

## 系统原生补帧（Mac、iPhone／iPad、Apple TV）

- **是什么：** RIFE 之外的另一种补帧，用 Apple VideoToolbox 的帧处理器在图形处理器和神经引擎上补帧，系统自带，不需要下载模型。「画质优先」用帧率转换（VTFrameRateConversion），鬼影最少；「低功耗」用低延迟插帧（VTLowLatencyFrameInterpolation），更省电，只有 2 倍和 4 倍。
- **范围：** 处理 1080p 以内（画质优先最高 1920×1200）、30 fps 以内的 SDR 视频；4K、高帧率、HDR、隔行片源和倍速播放保持原帧，并提示原因。镜头切换和停住的画面不补（直接重复原帧），免得拉出鬼影。
- **跟不上时：** 按每对源帧的实际耗时判断。「画质优先」持续超过一帧的时间预算时，这一集先改用低功耗；还跟不上就恢复原帧，并提示可以改用低功耗或 2 倍。
- **Mac：** 「设置 → 视频」的「系统原生补帧」（关闭、画质优先、低功耗）和「原生补帧输出帧率」（2 倍、60 fps、跟随屏幕刷新率，最多 5 倍），重新打开视频后生效，也可以在专业模式的「补帧」页边看边切换。开启后由它代替 RIFE。滤镜编进了 Mac 的播放内核（mpv 0.41.0 加上一个补丁），硬件解码选「复制回显」时这一集改用零拷贝的硬件解码。
- **iPhone／iPad：** 同样两项在「设置 → 视频」；ProMotion 屏幕上「跟随屏幕刷新率」补到 120 fps。iPad 上开启后代替 RIFE。
- **Apple TV：** 「播放设置 → 原生补帧」。tvOS 只有低延迟插帧，固定 2 倍（23.976 帧变 47.95 帧）；电视通常是 60 Hz，4 倍反而更不均匀。
- **一起看：** 开着原生补帧时和 RIFE 一样靠停帧对齐，不再微调倍速：原生补帧在快于 1 倍时保持原帧，追进度时的微调会让画面在补帧和原帧之间来回切换。

## Mac

Mac 上一个安装包是 2.9.5.9。Windows 这一版的共用改动随这个安装包到 Mac 上：

- **首屏：** 没有选定服务器时，先选择「本地播放」或「连接媒体服务器」，右上角固定有「设置」按钮。
- **显示器 ICC 色彩配置：** 「设置 → 视频」。Mac 上「自动」在支持 EDR 的屏幕（例如 MacBook Pro 的 XDR 屏）上不读 ICC，交给系统色彩管理，和 2.9.x 相同；其他屏幕读取显示器的 ICC。「始终使用」和「不使用」不看屏幕。专业模式「色彩」页可以边看边切换。
- **字幕垂直位置：** 「设置 → 字幕」，0–150，100 贴着画面底部，-1 按「字幕位置」。
- **一起看：** 下一节的同步改动从这一版起也在 Mac 上。Mac 跳到关键帧后报告的落点改为画面实际所在的位置：Mac 的原生播放窗口只读播放内核已经报告过的位置，跳转刚完成时那还是跳转的目标（例如目标 20.010 秒、关键帧在 20.042 秒，报告的是 20.009 秒，关键帧间隔长的片源上会差出几秒）；现在等内核报告新位置后再告诉房间，最多等 0.2 秒。

## iPhone／iPad

- **下放桌面版的设置：** 「设置 → 视频」新增「系统原生补帧」和「原生补帧输出帧率」。「设置 → MPV」新增桌面版的画质参数：放大、色度放大和缩小算法，时间插帧和它的算法，去色带的轮数、阈值、范围和颗粒，S 形放大、线性缩小、抗振铃、色域映射、HDR 峰值估算、抖动位深、字幕混合，以及「回退缓存」。画质参数只在打开「用下方高级参数覆盖当前档位」时覆盖档位，和桌面版相同。「设置 → 字幕」新增「字幕粗体」（默认关闭，内置的思源黑体只有一种字重）和「字幕垂直位置」。
- **连接时可以换服务器（#42）：** 打开应用后连接上次的服务器超过 1 秒，画面中间显示「正在连接」和服务器地址，下面是「改用 …」（另一个记住的服务器，例如在家用的局域网地址和在外用的 ZeroTier 地址，一点就连）、「切换服务器」（中断这次连接，打开服务器列表；关掉列表回到「已停止连接」的提示页）和「离线媒体」。自建服务器的地址没有回应时，约 8 秒就停止并提示（以前要等页面加载超时，约 1 分钟），提示页上同样可以一键改用其他服务器。

## Apple TV

- **播放设置：** 首页右上角的「画质」改为「播放设置」。画质档位之外，加入桌面版也有的：原生补帧；音画同步模式、画面比例、视频去隔行、HDR 色调映射；网络缓存、回退缓存、缓存不足时自动暂停；最大输出声道、音量标准化、音画偏移（-300 到 +300 毫秒）；字幕的字号、文字颜色、边框粗细和颜色、背景、位置、垂直位置、粗体、ASS 样式覆盖。选中一项会列出它的选项。设置保存在这台 Apple TV 上，从下一个视频起生效；默认值保持以前的播放方式。
- **提示：** 有设置没能应用，或原生补帧保持原帧时（例如 4K 片源），播放控制栏下方写出原因。

## 一起看（Windows、Mac 与 Android）

同步引擎是 Windows、Mac、Android 和 iPhone／iPad 共用的网页代码，这些改动随这一版进入各平台的安装包。标明 Windows 的两项依赖补帧或按关键帧跳转，其他平台没有。

- **连续跳转只同步最后一次：** 在房间里点击或拖动进度条、按住方向键连续跳转时，房间只收到最后一次跳转（Windows 上取它之前最近的关键帧，Android 上就是跳到的位置）；本机先停在那里，等所有人都解出画面后一起开始。以前点一下进度条，其他人会依次收到暂停、跳转和播放。
- **补帧时对齐到关键帧（Windows）：** 开着 RIFE 补帧时，跳到关键帧约 0.25 秒就能解出画面，跳到任意位置要 1.6–7 秒。需要对齐的成员改为停在房间前方的关键帧上，等房间播到那里。
- **画面提示：** 同步对本机做了什么（在等谁、多久后开始、和房间差了多少）会在画面上提示。
- **换集：** 房间里播放时点「下一集」「上一集」、自动播放下一集或在播放列表里选集，整个房间一起换过去；2.9.5.8 只有自己换了。
- **片尾：** 片子在房间里已经播完时，不再反复跳到文件末尾之后的位置。
- **跟不上实时：** 跟不上实时播放的成员（例如显卡忙时补帧只有 0.5–0.75 倍速）每次对齐后几秒又落后。45 秒内第 4 次落后时，先在后面接着播 1 分钟，并提示原因。
- **Mac 2.9.5.9 的修复：** 解出画面才开始、比房间快一点时停在当前画面等房间、跳转 4 次没赶上先接着播，这一版起也在 Windows 和 Android 上。
- **暂停后继续（Windows）：** 暂停 5 秒以上再继续时，补帧的预热不再让本机比房间晚一秒以上开始。

## Android

Android 上一个安装包是 2.9.5。这一版把 Windows 后来做的、Android 也用得上的改动带过来，并补上 Android 播放器缺的几项。

- **跳过片头（#39）：** 按 Emby 的「片头跳过模式」，进入片头后在画面右下角显示「跳过片头」按钮（控制栏出现时移到它上方；用遥控器或键盘时按钮自动获得焦点），或者直接跳过并提示「已跳过片头」。条件和 Windows 2.9.5.8 相同：服务器启用了片头检测，并且 Emby Premiere 有效；一起看房间里只显示按钮，不自动跳过。
- **外挂字幕改到后台加载：** 服务器单独提供的字幕（例如 Emby 从大文件里提取的字幕）改到后台加载。以前它在界面线程上加载，服务器准备得慢时界面要等它加载完。现在选中的外挂字幕还在由服务器准备时，画面显示「正在加载字幕…」，最多等 10 秒就先开始播放并提示「服务器还在准备字幕」，准备好后自动显示；最后没有拿到时提示加载失败，可以在字幕菜单里重新选择。和 Windows 2.9.5.6 的做法相同。
- **字幕粗体和垂直位置：** 「设置 → 字幕」新增「字幕粗体」（Android 默认关闭，Windows 和 Mac 默认开启）和「字幕垂直位置」（0–150，100 贴着画面底部，-1 按「字幕位置」）。HDR 直出时字幕由客户端自己绘制，也按这两项显示。
- **一起看的提示：** 按各自的时长显示（1.5–16 秒，以前一律 3 秒），改用原生提示框，HDR 直出时也看得到（以前播放内核的提示在 HDR 直出时不显示）。
- **跳转信号：** 播放器向页面报告跳转的开始和画面解出，一起看可以等画面解出再开始，和桌面端相同。
- **诊断日志：** 记下播放是怎么结束的（播完、停止、出错）和结束时的位置，随故障报告上传。

**Windows 2.9.5.3–2.9.5.8 里 Android 也用得上的改动**

- **播放启动：** 服务器响应慢时启动计时从 30 秒放宽到 75 秒，缓存还在增长时继续等；播放出错后在询问是否重试的对话框里选择不重试时，Emby 网页不再抛出内部错误。
- **服务器写进网页的美化和扩展（#33）：** 连接 Emby 4.8–4.10 时不再运行服务器写进网页的脚本和样式表；其他版本只隐藏美化脚本的加载遮罩。
- **评论：** 评论服务没有回应时自动再发一次，不会重复发表；发送被取消时提示「评论没有发出去，请再点一次」。
- **首页（#38）：** 快速划过底部海报时主视觉不再重影、断层。
- **弹幕：** 大河服务器 API 额度用完时提示「大河服务器API额度已耗尽，请明日重试」。

## 安装

## 已知问题

- 系统原生补帧只在 Mac（M4 Pro）上实测过画质和性能。iPhone、iPad 和 Apple TV 上只在模拟器里验证了设置、滤镜注册和提示（模拟器没有帧处理器，提示保持原帧），没有在真机上播放补帧；真机上不支持所选方式时会提示并保持原帧。
- Mac：一起看的这一版改动没有在真实的多人房间里试过；首屏的使用方式选择和 ICC 设置在 Mac 上看过，ICC 只在 MacBook Pro 的 XDR 屏（EDR）上试过，没有在外接的普通屏幕上试过。
- Mac：`test_mpvconf_editor_webengine` 在 Mac 上仍是已知的失败（默认 mpv.conf 的行数对不上，原因见 2.9.5.9 的说明），SVP 的问题也仍在：本次运行中开始播放过以后，在设置里保存 mpv.conf 会丢掉 SVP 的连接设置，要到下次打开客户端才能重新连上。
- Apple TV：播放设置在模拟器里验证了选择和应用；HDR 色调映射、声道和音画偏移没有在电视和功放上实际听看过。
- Windows：RTX 超分辨率在开发机（RTX 4090）上，驱动接受了滤镜、画面按倍数放大，但和 d3d11vpp 的普通放大几乎一样（同一帧平均每像素差 0.3／255），看不出 AI 超分的效果，可能是 NVIDIA App 里「超分辨率」的开关没开。画质效果没有验证；打开后看不出变化时，请先检查 NVIDIA App 的设置。RTX Video HDR 在同一台机器上生效（输出为 BT.2020／PQ）。
- Windows：VFG 只在开发机（RTX 4090）上实测，RTX 40 的其他型号和 RTX 50 系还没验证；高倍数、4K 片源和「高」档会明显增加显卡负载。
- Windows：开着 RTX 视频增强时，排在 RTX 后面的软件滤镜处理不了 RTX 输出的显存画面，mpv 会报错并关掉那个滤镜。客户端自己的 RIFE 和 VFG 总是加在 RTX 前面，不受影响；SVP 这类外部程序在播放中加的滤镜，如果加在了 RTX 后面，可能被关掉。SVP 和 RTX 同时使用还没有测试，遇到 SVP 不生效时请先关闭 RTX 视频增强。
- 一起看的这些改动只在同步引擎的模拟测试和 Windows 真实客户端里验证，没有在真实的多人房间里试过，Android 上也没有在房间里试过。
- Windows：IPv6 连不通时改用 IPv4（2.9.5.7）没有在这样的网络上实测。
- Windows：音画不同步的自动处理只在开发机上模拟验证过；每次打开客户端后的第一个视频仍可能先偏差几秒再切换。升级后仍然不同步、又没有看到「已改为跟随音频时钟」的提示时，请在不同步时用「故障报告」上传诊断日志。
- Windows 与 Android：服务器准备字幕超过 10 秒时，开头一段没有字幕；服务器一直不返回时字幕不会出现，也不一定有失败提示。
- Windows：不开补帧、使用默认的「显示器重采样」时，部分高刷新率环境下窗口播放仍可能持续卡顿、增加输出丢帧，全屏正常。这个问题 3.0.0 仍未修复；遇到时请先全屏播放，见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
- Windows：窗口播放剩下的抖动主要来自系统合成，和桌面活动有关（例如任务栏时钟显示秒数时，桌面每秒重绘一次）；全屏最平滑。
- 每帧实际时长和容器标的帧率对不上的视频不补帧，保持原帧播放。目前补帧用的是容器标的平均帧率，帧率判定方式还没改。
- Windows：RIFE 补帧时播放如果卡顿一下（例如别的程序突然占满显卡），可能把这一集误判成变帧率，状态显示「变帧率视频保持原帧播放」，这一集剩下的部分不再补帧。重新打开这一集会重新判断。
- 本地播放还不能把文件直接拖进已经打开的窗口（拖到程序图标或快捷方式上可以），也不记录本地文件的续播位置。
