本次发布 **Windows、Android、Mac、iPad 与 Apple TV**。Windows 与 Android 先发布；Mac、iPad 与 Apple TV 在 Mac 上构建验证后于同日补充到本页，它们的上一版是 [2.8.0](2026-10-16-v2.8.0.md)，2.9.0–2.9.3 中适用于苹果三端的改动都包含在这一版里，见下文「[Mac、iPad 与 Apple TV](#mac、ipad-与-apple-tv)」。Windows 运行库与修补版 QtWebEngine 与 [2.9.0](2026-10-19-v2.9.0.md) 相同，Android 的 JNI 原生库也与 2.9.0 相同。

## HDR

- **Windows：** 以前 Windows HDR 关闭时 HDR 片源只能色调映射为 SDR；开启时 Windows 报告的 HDR 校准配置文件又被当成色彩目标，HDR10 片源被渲染成约 416 nits 的 SDR 画面。现在播放 HDR 片源前，如果显示器支持 HDR 而 Windows 没有开启，客户端自动开启系统 HDR（设置「播放 HDR 时自动开启系统 HDR」，默认开启），播放 SDR 片源、空闲约 8 秒或退出时恢复；只恢复客户端自己打开的那一次，异常退出后下次启动也会恢复。系统 HDR 开启时以 HDR10 输出，并按显示器自身的峰值亮度映射。切换显示模式时屏幕会黑一两秒。
- **Android：** 在支持 HDR 的屏幕上，HDR10 与 HLG 视频用 MediaCodec 直接输出，由系统合成 HDR 图层，不再由播放器色调映射成 SDR。文本字幕仍按字幕设置显示；图形字幕和没有 HDR10 基础层的杜比视界继续走色调映射。不支持 HDR 的屏幕保持色调映射，画面和字幕效果更好。
- **Android HDR 提示：** 开始播放时左上角显示几秒输出方式和片源、输出的色彩空间，文字与 Mac、iPad 相同。
- **Android 旋转：** 旋转屏幕不再重新打开视频输出（以前每次旋转都会重启解码器）。部分系统在旋转时会截一张 SDR 画面做动画，屏幕亮度可能闪一下，这是系统的旋转动画所致。

## 更新提醒

- 有新版本时，每次打开软件弹窗一次。检查在后台进行，不拖慢启动；如果你已经开始操作时检查才完成，这次不打扰，结果留到下次打开时立刻显示，同时在后台重新核对。
- 更新窗口提供「从GitHub获取更新」「夸克网盘」「百度网盘」「忽略本次更新」和「稍后」。网盘按钮在浏览器中直接打开网盘里这个版本的文件夹，登录网盘后下载，适合无法访问 GitHub 时手动下载安装包（Android 上夸克的手机网页只能打开分享首页，需再点进版本文件夹）；「忽略本次更新」直到下一个新版本发布前不再弹窗。
- 在「客户端」设置中关闭「启动时检查更新」后既不检查也不弹窗。

## Windows 卡死报告

- 一份 Windows 报告显示播放 HLS 后 Qt 主线程卡住约 30 秒，卡顿结束时启动计时器又把刚要开始的播放判为失败，原因未能复现。现在主线程停止响应 5 秒时会记录各线程的调用栈；卡住或视频启动超时时，自动向服务器管理员发送「自动故障报告」，附带脱敏诊断日志和正在播放的作品，每次运行最多 3 份，可在客户端设置中关闭。
- 启动计时器到点时会等待原生层迟到的回应，不再把卡顿刚结束时开始的播放判为失败。
- mpv 的流探测恢复为默认的「auto」，只对 MP4 与 Matroska 跳过完整探测。

## Mac、iPad 与 Apple TV

- **Jellyfin：** 三端都可以连接 Jellyfin。Mac 与 iPad 使用与 Windows 相同的网页界面，Apple TV 使用原生页面。已在 Jellyfin 10.9.11、10.10.7、10.11.0、10.11.11 与 12.2 的根路径和 `/jellyfin` 子路径上，分别用 Mac 打包应用、iPad Pro 和 Apple TV 4K 真机完成登录、浏览和播放（各 10 组）。
- **服务器列表：** 记住连接过的自建 Emby／Jellyfin 服务器，可以直接切换；新地址确认能打开后才替换原来的连接，切换失败不会丢掉当前登录。
- **HDR（Mac、iPad）：** 在支持 HDR 的屏幕上（如 MacBook Pro 的 XDR 屏、iPad Pro），HDR10 与杜比视界直接以 HDR 输出，高光不再被压到 SDR 白；普通 SDR 屏幕保持以前的色调映射。开始播放时显示 4 秒输出方式和片源、输出的色彩空间（Mac 在右上角，不与弹幕提示重叠）。Apple TV 的输出方式不变。
- **Mac 更新提醒：** 与 Windows 规则相同：有新版本时每次打开软件弹窗一次，检查在后台进行；可「从GitHub获取更新」、打开夸克或百度网盘的版本文件夹、「忽略本次更新」或「稍后」。下载核验大小和 SHA-256 后打开 DMG，把新版拖入「应用程序」替换即可。
- **Mac 界面：** 继续使用修补版 QtWebEngine，界面动画跟随显示器刷新率（120 Hz 屏上约 120 帧）。
- **Mac 故障报告：** 与 Windows 相同，主线程停止响应或视频启动超时时，自动向服务器管理员发送附带脱敏日志的故障报告（Mac 不含线程调用栈），每次运行最多 3 份，可在客户端设置中关闭。
- **iPad 补帧：** 10 位 SDR 片源（常见于 HEVC 编码的动画）也改由 Metal 完成 RIFE 前的颜色转换。以前这类片源退回 CPU 转换，每帧要 9–16 毫秒，播放约 9 分钟后开始持续掉帧；现在约 3 毫秒，整帧处理回到 32 毫秒左右（23.976 fps 每帧预算 41.7 毫秒）。
- **空间音频（iPad、Apple TV）：** 戴 AirPods 播放 5.1／7.1 音轨时保留多声道，由系统做空间音频，控制中心里可以打开「空间音频」（Apple TV 在控制中心选中 AirPods 那一项进入）。以前会先混成立体声。杜比全景声的高度信息仍会被解码成 5.1／7.1 声道。
- **iPad 妙控键盘：** 上／下键调系统音量，左／右键快退／快进 15 秒，按住右键临时倍速、松开恢复，空格暂停。
- **iPad 更新：** 与之前相同，只检查并提示新版本，不在应用内下载安装。
- **Apple TV：** 同步升级版本、Jellyfin 支持和上面的空间音频。电视端仍不包含「一起看」和 RIFE。

## 安装

- `TigerestTheater-2.9.3-x64.exe`：Windows 安装版；或完整解压 `TigerestTheater-2.9.3-x64.zip` 便携版。Windows 2.5.1 及之后可用内置更新，更新前完全退出客户端；便携版保留 `data`。未做 Authenticode 签名。
- `TigerestTheater-2.9.3-android.apk`：Android 15+，沿用原签名，可覆盖升级并保留登录。
- `TigerestTheater-2.9.3-arm64.dmg`：Apple Silicon Mac，macOS 26+。打开后把应用拖入「应用程序」替换旧版。Mac 2.8.0 内置更新会找到这个文件。使用 ad-hoc 签名，未经 Apple 公证。
- `TigerestTheater-2.9.3-ipad.ipa`、`TigerestTheater-2.9.3-tvos.ipa`：iPad（iPadOS 26+）与 Apple TV（tvOS 26+）。IPA 不含签名，需要用自己的 Apple 身份签名后安装；两种包不能互换。见 [iPad 安装说明](../apple/INSTALL.md)与 [Apple TV 安装与构建](../../apple/TV/README.md)。
- `TigerestTheater-2.9.3-APPLE-SHA256SUMS.txt` 校验 Mac、iPad 与 Apple TV 文件；`APPLE-RELEASE-MANIFEST.json` 记录来源提交和验证范围；源码为 `apple-Sources.zip`。
- `TigerestTheater-2.9.3-SHA256SUMS.txt` 校验 Windows 与 Android 文件；`RELEASE-MANIFEST.json` 记录来源提交和验证范围。源码：`client-Sources.zip`、`android-Sources.zip`。
- 无法访问 GitHub 时，可从[夸克网盘](https://pan.quark.cn/s/88e6f7a795b4)或[百度网盘](https://pan.baidu.com/s/58azzOU4piiB3miyZqA1dig)的 `2.9.3` 文件夹下载同样的 Windows／Android 安装包，用 `SHA256SUMS.txt` 校验。Mac、iPad 与 Apple TV 的安装包目前只在 GitHub 发行页提供。
- 修补版 QtWebEngine 组件未改变，仍为 [2.9.0 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.0)的 `TigerestWebEngine-6.9.3-d3d11.zip`。
- 已安装的 Windows RIFE 扩展可以继续用于 2.9.3。

- **Windows 发布构建：** 完整串行 CTest 112 个目标全部首轮通过；条件跳过与 2.9.1 相同（需独占桌面指针的窗口测试、需私有 RIFE 运行库的测试），无边框最大化检查实际执行。便携包 1532 个文件与暂存目录逐字节一致，OpenSSL、mpv 与修补版 WebEngine 的固定哈希全部匹配。在空目录中只用包内运行库即可启动。

## 已知问题

- 部分 Windows 高刷新率环境下，窗口播放可能持续卡顿、增加输出丢帧，而全屏正常。2.9.3 仍未修复，请先使用全屏播放，见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
- 无法访问 GitHub 时，客户端目前也查不到新版本（检查本身走 GitHub）；社区服务器的备用查询会在之后的服务端更新中提供；在此之前请从上面的网盘链接手动下载。
- 真实媒体库中进入媒体库或详情页时，网页主线程仍可能有 70–160 ms 的长任务，表现为一次短暂停顿，后续优化。
- Mac 更新窗口的网盘按钮会打开网盘里的 `2.9.3` 文件夹，但其中目前只有 Windows／Android 安装包；Mac 请从 GitHub 获取更新。
- Apple TV 仍不支持「一起看」和 RIFE；iPad 与 Apple TV 的 IPA 需要自行签名。
- Jellyfin 服务器缺少共同作品身份时，同一作品的两个条目仍可能分开显示；同名的不同作品不会按标题合并。
