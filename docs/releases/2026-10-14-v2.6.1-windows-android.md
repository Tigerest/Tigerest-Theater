# Tigerest Theater 2.6.1 · Windows 与 Android

| 平台 | 安装包 | 系统要求 |
| --- | --- | --- |
| Windows 安装版 | [2.6.1 EXE][dl-win-exe] | Windows 10 1903+ / Windows 11，x64 |
| Windows 便携版 | [2.6.1 ZIP][dl-win-zip] | 同上；完整解压后运行 |
| Android | [2.6.1 APK][dl-android] | Android 15+，arm64-v8a / x86_64 |

Windows 客户端的网页界面跟随显示器刷新率运行，并打开平滑滚动。Windows 与 Android 同时带上本轮共用网页界面的转场优化。Mac 与 iPad 的变化见 [2.6.1 发布说明](2026-10-14-v2.6.1.md)。

## Windows 界面不再固定 60 帧

之前 Windows 客户端里所有网页动画（首页、媒体库、详情页转场，CSS 动画，滚动）都固定 60 帧，与显示器刷新率无关。原因在 QtWebEngine：网页画面先画到离屏纹理再交给 Qt 合成，这条路径下 Chromium 合成器的出帧计时器从未收到屏幕刷新率，一直使用默认的 1/60 秒。

自建 QtWebEngine 增加补丁，每秒读取窗口所在屏幕的 vblank 时间和刷新周期并交给合成器。多屏刷新率不同时以窗口所在屏幕为准；参数每秒重新读取，窗口换屏后的切换尚未单独验证。

在 4K 240 Hz / RTX 4090 上，同一 DLL 开关对照（仓库模拟数据，窗口最大化）：

| 转场 | 2.6.0 | 2.6.1 |
|---|---|---|
| 首页 → 详情 | 59–60 fps | 187–213 fps |
| 媒体库 → 详情 | 58 fps | 179–183 fps |
| 详情 → 返回 | 57–58 fps | 185–186 fps |
| 首页 → 媒体库 | 53–54 fps | 143–145 fps |
| 媒体库 → 首页 | 43–47 fps | 109–139 fps |

帧间隔 p95 从 16.8 ms 降到 8.4 ms。120 Hz、144 Hz 屏幕按各自刷新率运行。

## 平滑滚动

QtWebEngine 默认关闭滚动动画，鼠标滚轮和网页的 `scroll-behavior: smooth` 都是一下跳到位。2.6.1 打开滚动动画，并把每格滚轮距离由 60 px 加大到 150 px（Chrome 为 100 px），仍跟随系统“每次滚动行数”设置。距离经过 60／100／150 px 三轮试用后选定。

## 与 Mac／iPad 共用的改动

- 共用网页界面的转场优化同样进入 Windows 与 Android：复用已解码的作品图片、减少转场开始和快照中的工作、停止过时的预热。Mac 专用的后台模糊背景与 iPad 原生毛玻璃不在这两个平台启用。
- 启动时的更新检查改为后台进行，不再阻塞网页接口就绪。
- Windows 弹幕自动匹配读取作品别名，与 iPad 一致；宽泛搜索时每个接口最多再读五个弱匹配作品的详情，减少等待。
- Android 原生部分（播放器、原生库、签名）与 2.6.0 相同。

## 已知问题

- 部分 Windows 高刷新率环境下，窗口播放可能持续卡顿、增加输出丢帧，而全屏正常。2.6.1 仍未修复；请先使用全屏播放。详见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
- 在真实媒体库全屏使用时，剧集页进入详情页的转场约 110–127 fps，其中可能有 80–270 ms 的单帧停顿。停顿来自网页端搭建详情页和解码海报的主线程工作，与帧率上限无关，后续优化。
- 约 3% 的帧会停留两个刷新周期（240 Hz 下 8.3 ms），肉眼不易察觉。

## 验证范围

- 帧率数据来自隔离配置、仓库模拟数据和真实 GPU 的自动化测量，以及用户在真实服务器上的手动试用（浏览、转场、滚轮，未发现明显问题）。用户试用的是合并 Mac／iPad 改动之前的 Windows 构建；合并后的版本由完整自动测试覆盖。
- Android 只运行了 JVM 测试、lint 和安装包检查；共用网页界面的改动未在 Android 真机上验证。
- 花屏修复（D3D11 生产者等待）保留；开启时 240 Hz 下帧率与关闭时无可测差别。原有花屏复现脚本对旧版也已不再触发，因此花屏未回归依赖用户手动检查。
- 真实视频播放与弹幕、窗口拖到 60 Hz 副屏的切换、动画期间的功耗未单独验证。
- 调查过程和未采用的方案见[调查记录](../reports/2026-10-14-windows-frame-pacing.md)。最终构建的测试、签名与附件哈希以发行页的 `TigerestTheater-2.6.1-RELEASE-MANIFEST.json` 与 SHA-256 清单为准。
