# Tigerest Theater 2.9.4 · mpv.conf 编辑器与自动安装更新

本次发布 **Windows、Android、Mac、iPad 与 Apple TV**。Windows 与 Android 先发布；Mac、iPad 与 Apple TV 在 Mac 上构建验证后于同日补充到本页。Windows 改用新的修补版 QtWebEngine（在 2.9.0 的四个补丁上增加两个，共六个）；Android 的 JNI 原生库与 2.9.0 相同。

## 更新下载与安装

- **直接下载：** 更新窗口里的「从GitHub获取更新」改叫「直接下载」，先经 GitHub 下载加速镜像 gh-proxy.com，不行换 ghproxy.net，最后才连 GitHub 原址，进度旁边显示正在用哪个。下完仍按 GitHub 官方接口给出的大小和 SHA-256 核对，镜像下载的文件对不上时直接从 GitHub 重下一次。Mac 下载 DMG、Windows 下载 RIFE 扩展同样走镜像。
- **备用下载：** 夸克和百度网盘按钮收进「备用下载」，点开才显示；直接下载失败时自动展开。
- **Windows 自动安装：** 点「安装更新」后大河影院自己关闭，静默安装，装完自动重新打开；装在「所有用户」目录时会有一次系统权限提示。正在播放时等播放结束再装。从 2.9.3 及更早版本升级的这一次仍是原来的安装向导，之后的更新才是全自动的；便携版仍要手动替换。
- **Android 安装：** 下载核验后用系统的安装会话直接安装，只剩系统的安装提示要点；第一次需要允许大河影院安装应用。安装时应用会被系统关闭，装好后从桌面重新打开（Android 不允许应用在更新后自己启动）。
- **检查更新：** 先向社区服务器请求签名的版本列表（Ed25519 签名，客户端验签，72 小时内有效），不再占用 GitHub 的匿名访问额度，也就不容易再看到「GitHub 请求受限」。签名不对、过期或连不上时自动改问 GitHub，和以前一样。Windows、Android、Mac 与 iPad 都改为这样检查。

## mpv.conf 编辑器（Windows 与 Mac）

- 客户端只读取自己配置目录里的一份 `mpv.conf`，在「设置 → 播放器设置 → MPV 画质与插件」下方的编辑器里修改。文件分三块：头部和尾部由客户端维护（脚本、SVP 接口、启动档位，以及视频、字幕、音频页决定的值），中间的用户区自由修改。
- 表单和文本实时同步，左侧「＋」插入画质参数、着色器、vf 滤镜或新建自定义档位（`tigerest-user-` 开头，会出现在画质预设和 uosc「滤镜」菜单里）。逐行检查并标红；有错误时离开设置页会询问「强行使用」还是「返回修改」。
- 保存后立即生效，不用重启；设置页的画质预设、uosc「滤镜」菜单和 Alt+1/2/3 切档都按当前的 mpv.conf 执行，播放中切档后设置页的预设也会同步。
- 「恢复默认配置」「粘贴整份配置前先看差异」「复制给 AI」（附带自动生成的修改规则）和使用说明都在编辑器里。
- RIFE 开启时，自己写的改帧率 vf 滤镜和 `interpolation=yes` 暂时注释成 `#[暂停执行:RIFE]`，关闭 RIFE 后恢复，设置页底部会提示。
- 自己的着色器放在 `shaders/user/`，升级不会改动它；内置着色器按清单更新，旧版留在着色器根目录、没有改过的 52 个重复 Anime4K 文件自动删除（Windows 2.9.3 装的是 CRLF 换行的副本，同样识别）。滤镜库清单列出每个着色器的作用、触发条件、开销、强度和在 Apple M4 Pro 上实测的耗时。
- mpv 用当前配置启动失败时，自动改用默认配置并提示，不再直接退出。
- **升级迁移：** 第一次打开 2.9.4 时写入新的默认配置。原来的内置／自动／系统三种配置模式、「高级」页的手动 MPV 配置和 `user-overrides.conf` 不再使用；旧的 `user-overrides.conf`、高级选项和画质覆盖参数原样备份到配置目录的「旧版自定义配置备份.txt」，`user-overrides.conf` 删除。系统里的 mpv 配置不会导入。
- **设置菜单：** 左侧菜单新增「播放器设置」分组（客户端、视频、音频、字幕、MPV 画质与插件、弹幕样式），原来的分组改名「媒体库设置」，Android 的左侧菜单也一样分组；「高级」页隐藏。「恢复本页默认值」改在页面里确认：以前的系统确认框可能弹在看不见的地方，把整个设置页卡住；恢复时也不再重置隐藏的迁移标记。
- 默认配置下 SVP 的 `mpvpipe` 接口照常提供；开启 RIFE 时暂时移除，关闭后恢复。

## 海报转场（Windows、Mac 与 Android）

- 点海报后海报直接飞向详情页的落点，不再停在半空等新页面。落点按优先级取：上次记住的落点、离开时卡片的位置，或按 Emby／Jellyfin 详情页布局算出的位置（Emby 与 Jellyfin 实测误差 0–0.4 px）；都没有时原地抬起，等目标出现再飞。
- 按点击后 700 ms 的截止时间落地：目标页面按时出现时 0.6–0.7 秒落地；目标太晚出现时海报原地淡出，页面在下面揭开。
- 从详情页返回海报墙时，按下返回就提前发出海报墙的查询；Emby 直接加载屏幕上需要的部分，揭开时不再出现空行。
- 修复进入详情页时偶尔闪白，以及起飞时被点的卡片位置先空一两帧。
- **Windows：** 修补版 QtWebEngine 把 GPU 着色器缓存保存在当前配置的缓存目录（`GPUCache`）里，重启后第一次转场不用再现编译着色器；以前每次启动后的第一次转场会多卡约 65 ms。另一个新补丁是默认关闭的网页帧率上限，只用于对比测试。
- **Android（10 月 24 日更新的安装包）：** 能预测落点时（上次记住的落点、离开时卡片的位置或按布局算出的位置），海报先飞到落点，落地后才打开新页面：手机上加载中的页面会卡住移动中的海报，这样飞行途中不再卡顿。海报约 0.6 秒落地，落点有偏差时就地校正，然后直接揭开新页面；进详情页整个转场约 1.0–1.2 秒，返回海报墙约 0.9 秒（2.9.3 为 1.2–1.7 秒）。预测不到落点时仍先把海报抬起、等新页面稳定后再飞。
- iPad 与 iPhone 改用桌面流程，见下文。Mac 随苹果三端的 2.9.4 一起更新。

## Android 图标（10 月 24 日更新的安装包）

- 桌面图标换成和其它平台一样的黑金 Tigerest 图标（原来是占位的黄色播放三角），也支持 Android 的主题图标。

## 弹幕（Windows、Mac、iPad 与 Apple TV）

- 底部弹幕改为和普通弹幕一样滚动显示，不再固定压在画面最下方；画面底部 20% 始终留给字幕，「弹幕显示范围」选 85% 或 100% 时按 80% 显示。
- 修正弹弹play 备用格式里顶部、底部弹幕类型颠倒的问题。

## iPad 与 iPhone

- iPad 版改为 iPhone／iPad 通用包：iPhone 上网页按窄屏排版，竖屏播放器的控制栏分成时间和按钮两行，在 iPhone 上不再自称 iPad。
- 安装包改名为 `universal.ipa`，应用标识改为 `top.tigerest.theater.universal`：会作为新应用安装，不覆盖旧的 iPad 版，登录、设置和离线媒体需要重新来；旧版可在确认新版正常后手动删除。
- 转屏后画面正确铺满（iPad 也一样）。
- 海报转场改用与 Mac、Windows 相同的流程：按下即起飞，约 600 ms 落地（原来 1.1–1.5 秒）；网页动画从 60 帧提到 120 帧。从详情页回海报墙时停在离开的位置，不再自己滚动、海报不再中途改道；点海报和回首页时画面不再闪暗。
- 从屏幕左边缘向右滑动即返回上一层（与顶栏返回相同，带转场）；在首页左滑不再退到空白页面。
- 设置页（手机从「设置」进入的那一页）与桌面菜单一样分成「媒体库设置」和「播放器设置」两组。
- 登录等输入框获得焦点时不再把页面放大且不恢复。
- 开着 RIFE 持续掉帧时按桌面规则提示，画质设置里能看到丢帧数和推理 p95。
- 播放中打开「硬件解码」不会再偶尔退回软解。

## Apple TV

- 遥控器返回键先收起播放控制栏，再按一次才退出播放。
- 媒体库海报墙可以排序（名称、最近添加、发行时间、评分）和搜索。
- 海报和剧集卡片显示「N 集未看」「✓ 已看」和观看进度条，详情页显示已看完、看到百分之几或未看。
- 文字字幕放大约 15%。

## 安装

- `TigerestTheater-2.9.4-x64.exe`：Windows 安装版；或完整解压 `TigerestTheater-2.9.4-x64.zip` 便携版。从 2.9.3 及更早版本更新时完全退出客户端后安装；便携版保留 `data`。未做 Authenticode 签名。
- `TigerestTheater-2.9.4-android.apk`：Android 15+，沿用原签名，可覆盖升级并保留登录。10 月 24 日换成加入上述 Android 海报转场和新图标的构建，版本号不变；10 月 23 日已装 2.9.4 的设备不会收到更新提示，需要时重新下载这个 APK 覆盖安装（保留登录）。
- `TigerestTheater-2.9.4-arm64.dmg`：Apple Silicon Mac，macOS 26+。打开后把应用拖入「应用程序」替换旧版；Mac 2.9.3 的更新窗口会找到这个文件。使用 ad-hoc 签名，未经 Apple 公证。
- `TigerestTheater-2.9.4-universal.ipa`：iPhone 与 iPad 通用（iOS／iPadOS 26+），应用标识改为 `top.tigerest.theater.universal`，作为新应用安装；`TigerestTheater-2.9.4-tvos.ipa`：Apple TV（tvOS 26+）。IPA 不含签名，需要用自己的 Apple 身份签名后安装；两种包不能互换。见 [iPad / iPhone 安装说明](https://github.com/Tigerest/Tigerest-Theater/blob/main/docs/apple/INSTALL.md)与 [Apple TV 安装与构建](https://github.com/Tigerest/Tigerest-Theater/blob/main/apple/TV/README.md)。
- `TigerestTheater-2.9.4-ipad.ipa` 是旧构建，只为让 2.9.3 的 iPad 版能检测到更新而保留，请下载 `TigerestTheater-2.9.4-universal.ipa`。
- `TigerestTheater-2.9.4-APPLE-SHA256SUMS.txt` 校验 Mac、iPhone／iPad 与 Apple TV 文件；`APPLE-RELEASE-MANIFEST.json` 记录来源提交和验证范围；源码为 `apple-Sources.zip`。
- `TigerestTheater-2.9.4-SHA256SUMS.txt` 校验 Windows 与 Android 文件；`RELEASE-MANIFEST.json` 记录来源提交和验证范围。源码：`client-Sources.zip`、`android-Sources.zip`。
- `TigerestWebEngine-6.9.3-d3d11.zip`：本版 Windows 使用的修补版 QtWebEngine 组件（六个补丁），供构建工作流和自行重建使用，普通用户不需要下载。
- 无法访问 GitHub 时，可从[夸克网盘](https://pan.quark.cn/s/88e6f7a795b4)或[百度网盘](https://pan.baidu.com/s/58azzOU4piiB3miyZqA1dig)的 `2.9.4` 文件夹下载同样的 Windows／Android 安装包，用 `SHA256SUMS.txt` 校验。Mac、iPad 与 Apple TV 的安装包目前只在 GitHub 发行页提供。
- 已安装的 Windows RIFE 扩展可以继续用于 2.9.4。

## 验证范围

- **Windows 发布构建：** 完整串行 CTest 117 个目标首轮全部通过（565 秒）；条件跳过与 2.9.3 相同（需独占桌面指针的窗口测试、需私有 RIFE 运行库的测试）。三个新增的联网用例默认跳过，另行开启后通过：社区版本列表线上验签（30 个版本）、经 gh-proxy.com 下载 2.9.3 安装包（246 MB）并按 GitHub 的 SHA-256 核对、匿名读取两个网盘找到版本文件夹。自动安装由 `test_installer_handoff` 用真实的 Inno Setup 测试安装包验证：客户端自行退出、文件被替换、新版本从安装目录启动，安装被取消时客户端继续运行。
- **Windows 安装包：** 便携包 1534 个文件与暂存目录逐字节一致，OpenSSL、mpv 与修补版 QtWebEngine（六个补丁）的哈希与锁定值一致。解压到空目录、只保留系统目录 PATH 启动，Qt、WebEngine 与 mpv 都从包内加载，D3D11 fence 同步就绪，87 个内置着色器为 LF 换行，着色器缓存目录已创建。
- **mpv.conf 编辑器（Windows）：** 这批代码此前只在 Mac 上编译过；合并后 MSVC 编译无警告，交接说明列出的 Windows 测试（RIFE 私有接口、RIFE 生命周期、设置页、网页控制、编辑器端到端）都实际运行通过。真实客户端在隔离配置中、用本地生成的 1080p 测试片段检查了：默认配置下 SVP 的 `mpvpipe` 存在，开启 RIFE 时移除、关闭后恢复；RIFE 暂停与恢复提示；设置页预设和 Alt+1/2 切档、编辑器保存（全局选项、`@user` 滤镜、删除着色器）在播放中立即生效。用真实的 2.9.3 发布包升级一个隔离配置：生成了备份文件，`user-overrides.conf` 被删除，设置已迁移并提示，第二次启动不再迁移，根目录 52 个旧着色器被删除。没有用 Emby／Jellyfin 的真实片源从网页端播放来检查编辑器；滤镜耗时只有 Mac 的实测数据。
- **海报转场（Windows）：** 隔离配置连接真实的 Emby 4.10 与 Jellyfin 10.11 服务器，首页→详情、详情→海报墙、海报墙→详情各测 3 次（不录屏、着色器缓存已预热，以原生换帧时间计时），并录屏逐帧检查：目标页面按时出现时录屏测得 600–675 ms 落地，六种转场没有闪白。
- **Android：** JVM 单测 debug 141 个、release 138 个全部通过（各跳过 2 个只在手动开启时运行的联网用例），lint 0 个错误，签名证书与 2.9.3 相同，原生库与 2.9.3 逐字节相同并按 16 KB 对齐。正式包已覆盖安装到小米 MIX Fold 4（Android 16），外屏冷启动约 0.3 秒进入 Emby 首页。同一源码的调试版在同一台手机的外屏上连接 Emby：首页→详情、海报墙与详情之间往返共 5 次转场都正常落地（误差 0 px），飞行中帧间隔 p95 8.4 ms、最长 8.4–25 ms，整个转场 1.2–1.6 秒；设置抽屉的两组菜单、点击跳转和页面内确认框正常，网页没有脚本错误。没有在展开的内屏和 Jellyfin 上复测。应用内安装更新由单元测试覆盖，发布前没有比 2.9.4 更新的版本，未用正式包实际走一遍应用内升级。

## 已知问题

- 部分 Windows 高刷新率环境下，窗口播放可能持续卡顿、增加输出丢帧，而全屏正常。2.9.4 仍未修复，请先使用全屏播放，见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
- 返回一面这次还没显示过、图片也不在缓存里的海报墙时，服务器要 0.5–0.8 秒才给出目标卡片，转场约在 0.8–0.9 秒结束，超过 0.7 秒的目标。
- 转场中每次仍有几帧超过 17.7 ms（多数 2–5 帧，最长 31–51 ms），来自网页光栅化和主线程本身的耗时。
- Android 海报落地后揭开新页面时，仍有几帧 35–75 ms 的停顿。
- Mac 更新窗口的网盘按钮会打开网盘里的 `2.9.4` 文件夹，但其中只有 Windows／Android 安装包；Mac 请用「直接下载」。
- Apple TV 仍不支持「一起看」和 RIFE；iPad 与 Apple TV 的 IPA 需要自行签名。
