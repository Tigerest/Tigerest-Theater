## 服务器写进网页的美化和扩展（#33）

- **问题：** 服务器用 emby-crx 这类方式改写 Emby 的 `index.html` 后，多出来的脚本和样式表也会在客户端里运行。2.9.5.4 只隐藏了美化脚本的全屏加载遮罩，脚本本身还在运行，样式也还在改界面。
- **原因：** 客户端打开的就是服务器的这个网页。这些内容是给 Emby 自带网页写的，本客户端有自己的首页、弹幕和播放器。
- **修复：** 连接 Emby 4.8–4.10 时，客户端在解析网页的过程中去掉多出来的 `<script>` 和样式表 `<link>`，它们不会运行，也不会生效。写在同一个位置的网页版弹幕、外部播放器按钮等扩展同样不会运行。服务器不用改，用浏览器打开的 Emby 网页端不受影响。
- **范围：** 这几个版本的原版网页只有内联 importmap 和 `apploader.js` 两个脚本，其余模块都是解析完成后由 `apploader.js` 加载的，不受影响。Emby 4.11 及以后的原版网页还不确定，4.8 以前不在支持范围内，这些版本和 Jellyfin 的网页不做改动，仍只隐藏加载遮罩。
- **没有覆盖的情况：** 已有服务器的配置里新加一台服务器时，第一次打开还不知道它的版本，这一次不过滤，之后每次都过滤。写在网页里的内联 `<style>` 不会去掉，原版网页自己也有一段，分不出来。

其他功能与 2.9.5.4 相同。

## 安装

- `TigerestTheater-2.9.5.5-x64.exe`：Windows 安装版；或完整解压 `TigerestTheater-2.9.5.5-x64.zip` 便携版（保留 `data`）。在 2.9.5、2.9.5.1、2.9.5.2、2.9.5.3 或 2.9.5.4 的更新窗口点「安装更新」会自动关闭、静默安装并重新打开。2.9.4 的检查更新识别不了四段版本号，会先提示 2.9.5，装好后再检查一次就能升到 2.9.5.5，也可以直接运行这一版的安装包；从 2.9.3 及更早版本升级时完全退出客户端后运行安装向导。未做 Authenticode 签名。
- 播放内核和修补版 QtWebEngine 与 2.9.5.1 到 2.9.5.4 相同。播放内核的原始构建产物 `Tigerest-mpv-rife-x64-5122104.zip` 在 [2.9.5.1 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.5.1)，修补版 QtWebEngine 的组件包见 [2.9.4 发行页](https://github.com/Tigerest/Tigerest-Theater/releases/tag/v2.9.4)的 `TigerestWebEngine-6.9.3-d3d11.zip`。已安装的 Windows RIFE 扩展可以继续用于 2.9.5.5，不用重新下载。
- `TigerestTheater-2.9.5.5-SHA256SUMS.txt` 校验本页全部文件；`RELEASE-MANIFEST.json` 记录来源提交、内核来源和验证范围。源码：`client-Sources.zip`（全部客户端，标签 `v2.9.5.5` 对应的提交；Windows 安装包从其中的 `29a2b45` 构建，之后的提交只改文档）。
- 无法访问 GitHub 时，可从[夸克网盘](https://pan.quark.cn/s/88e6f7a795b4)或[百度网盘](https://pan.baidu.com/s/58azzOU4piiB3miyZqA1dig)的 `2.9.5.5` 文件夹下载同样的 Windows 安装包，用 `SHA256SUMS.txt` 校验。

## 验证范围

- **发布构建：** 安装包和便携包从 `29a2b45`（打开检查更新）构建。完整串行 CTest 125 个目标全部通过（573 秒）；`test_window_chrome` 单独运行 7 项通过、0 项跳过。
- **原版网页：** 读了 Emby 官方发行包里 4.8.0.80、4.8.11.0、4.9.5.0、4.10.0.40、4.10.1.0 的 `index.html`，以及本机安装的 4.9.3.0 和一台 4.10.2.0 服务器实际返回的页面：脚本都只有内联 importmap 和 `apploader.js`，都没有样式表 `<link>`。
- **过滤：** `test_server_skin_filter_webengine` 在真实客户端里打开按 emby-crx 写法做的模拟页面，这是模拟数据验证。上面 7 个版本上，多出来的脚本和样式表都没有生效，`apploader.js`、它之后加载的脚本和样式、importmap 和原版的内联样式都正常。Emby 4.7、4.11 和 Jellyfin 的页面没有被改动。还验证了全新配置第一次打开就过滤、不知道版本时这一次不过滤且下一次过滤、记住的版本过期时自动重新加载一次。
- **真实 Emby 页面：** 用本机代理给一台 Emby 4.10.2.0 服务器的页面加上 #33 报告里的 6 行，服务器本身没有改动。这 6 行都没有生效，真实的 Emby 网页正常走到登录页；把版本报成 4.11 时这些行照常运行。代理加上的文件是占位内容，不是真实的 emby-crx。
- **登录后：** 发布前用同一份代码的构建和全新配置，由开发者本人登录一台没有美化内容的 Emby 4.10.2.0，打开了首页、电视媒体库和条目页。这台服务器没有美化内容，只能确认这一版对普通服务器没有影响。
- **安装包：** 便携包 1534 个文件与暂存目录逐字节一致，OpenSSL、播放内核（两个 DLL 角色是同一份）与修补版 QtWebEngine 的哈希与锁定值一致；和 2.9.5.4 的便携包逐文件比较，只有主程序不同（这一版改动的脚本都编译在主程序里）。程序内的构建号为 `29a2b45d`，构建日期 2026-11-09。
- **便携包试用：** 便携包解压到新文件夹，在没有开发环境的命令行里用独立配置打开一段本机生成的 1080p 视频（文件名含中文），以 gpu-next、WASAPI 和 d3d11va-copy 正常开始播放。连续 4 次打不开视频，每次约 160 毫秒报错；强制音画不同步时日志里当时和 3 秒后各多一组数字；程序日志里没有乱码。上面的过滤测试和真实 Emby 页面检查也在这个包上跑过，结果相同。
- 自动测试和便携包试用使用隔离配置、离线夹具、本机服务和本地视频，试用关闭了自动故障报告。生产服务只收到只读请求（检查更新、公开的网页文件和服务器信息）。没有连接真实的 emby-crx 服务器，也没有在 Emby 服务器上验证这一版的播放。附件哈希以发行页的 `TigerestTheater-2.9.5.5-SHA256SUMS.txt` 和 `RELEASE-MANIFEST.json` 为准。

## 已知问题

- Windows：有用户反馈播放时音画不同步、感觉画面比声音快。这份日志里片源的时间戳正常，同一集在这台电脑上（120 Hz 显示器）没有复现，原因还没查清，这一版没有修复。遇到时可以在设置里把「音画同步模式」改成「跟随音频时钟」试试，下一份诊断报告里会带上音画偏差的数字。
- Windows：不开补帧、使用默认的「显示器重采样」时，部分高刷新率环境下窗口播放仍可能持续卡顿、增加输出丢帧，全屏正常。这个问题仍未修复；遇到时请先全屏播放，见[故障排查](https://github.com/Tigerest/Tigerest-Theater/wiki/Troubleshooting)。
- Windows：窗口播放剩下的抖动主要来自系统合成，和桌面活动有关（例如任务栏时钟显示秒数时，桌面每秒重绘一次）；全屏最平滑。
- Windows：全屏开着弹幕、按音频时钟播放时，10 分钟测试里出现过一次约 0.15 秒不出新画面（随后掉 2 帧），卡在处理弹幕图层的阶段，原因还没查清。
- Windows：2.9.5.1 的高刷新率节奏改进只在一台 4K 240 Hz 显示器和 RTX 4090 上实测，其他刷新率、显示器和显卡还没验证；也还没在 Emby 串流和网页界面下测过节奏。
- 每帧实际时长和容器标的帧率对不上的视频不补帧，保持原帧播放。目前补帧用的是容器标的平均帧率，帧率判定方式还没改。
- 本地播放还不能把文件直接拖进已经打开的窗口（拖到程序图标或快捷方式上可以），也不记录本地文件的续播位置。
- 返回一面这次还没显示过、图片也不在缓存里的海报墙时，服务器要 0.5–0.8 秒才给出目标卡片，转场约在 0.8–0.9 秒结束。
