# 首次使用引导（设计，2026-11-20 已确认）

参照 Sparkle 的引导：整页变暗，只亮出正在讲的那块界面，旁边弹出气泡。气泡里有粗体标题、两三行说明、「2 / 14」步数、「上一步」「下一步」按钮，右上角 ×。

## 一、怎么做

- **一套脚本，四个平台共用。** Windows、Mac、Android、iPhone/iPad 加载的是同一批网页注入脚本（`native/*.js`），引导写成新的 `native/onboardingTour.js`，三份脚本清单各加一行：桌面 `SystemComponent.cpp`、Android `WebHost.kt`、iOS `apple/tools/sync_resources.py`。
- **Apple TV 单独做。** 它是纯 SwiftUI 界面，没有网页，只能用 SwiftUI 另写一个同样外观的引导，步骤思路相同（见第六节）。
- **自己写，不用第三方库。** 引导大约 500 行。要亮出的位置会跟着首页入场动画移动，Emby 换页时还会重建顶栏，遥控器的按键也要由引导接住。现成的 driver.js（MIT）这几处都得改，自己写反而简单，也不用下载依赖。
- **外观跟着页面。** 深色界面用客户端菜单那一套：深底、金色细边、金色按钮。Emby 或 Jellyfin 选了浅色主题时，气泡换成白底深字。系统设置「减少动态效果」时，高亮框直接跳到下一处，不做移动动画。

## 二、何时出现

- **出现时机：** 登录服务器后第一次进入首页，等入场动画放完、作品载入后开始。启动页、登录页和播放中不会出现。只用「本地播放」的人先不弹，等第一次连上服务器进入首页再出现。
- **按配置档记录，不按安装。** 桌面和 iPhone/iPad 的每个配置档有自己的设置，新建一个配置档就和新装一样；Android 只有一个配置档。记录放在隐藏设置 `main.onboardingTour` 里。
- **新用户和升级用户都走完整引导（已选 C）：**
  - **新用户**（新建的配置档）不能跳过：没有 × 和「跳过」，欢迎卡上只有「开始」。Esc 和返回键退回上一步，在第一步时不起作用。
  - **从旧版本升级上来的用户**中途可以退出：右上角 ×、欢迎卡上的「跳过」、Esc 和返回键都会关闭引导。
  - **从设置里重新打开的引导**也可以随时退出。
- **怎么分辨新用户：** 读配置时判断。没有配置文件就是新用户；有配置文件、但里面没有引导这一项，就是旧版本留下的，算升级用户。
  - Windows 和 Mac 的 Qt 版在 `SettingsComponent` 里判断，Android 在 `SettingsStore` 里判断，各加几行。
  - iPhone/iPad 交给 Mac 那边在 `SettingsStore.swift` 里做同样的判断。判断不出来时按升级用户处理，也就是可以跳过。
- **记录的值：** `main.onboardingTour` 取下面这些值。
  - `new`、`upgrade`：等待自动弹出。
  - `replay`：从设置里点了重新打开。
  - `done`：走完。
  - `skipped`：中途退出。
  - `off`：测试用，永远不自动弹。
- **之后不再自动出现的情况：** 走完；或者在可以退出的引导里点「跳过」、点 ×、按 Esc 或返回键。
- **中断后再来一次：** 引导进行中如果开始播放（比如一起看的房间开播）或程序被关掉，算中断，下次进首页从第一步重新开始。新用户是否能跳过不受中断影响。

## 三、重看入口

- **网页四个平台：** 在「客户端 → 客户端设置」的按钮行里加「重新打开引导」，放在「检查客户端更新」「切换服务器」旁边，一处改动四个平台都有。点了就关掉设置、回到首页，从第一步开始。在启动页的设置里点它时，等连上服务器进首页再开始。
- **Apple TV：** 在「播放设置」里加同名按钮。

## 四、跳过规则

| 情况 | 处理 |
|---|---|
| 平台没有这个功能 | 直接不算进总步数。窗口/全屏和专业模式只在 Windows、Mac 有；「补帧与画质增强」只在 Windows（有 NVIDIA 显卡时）和 Mac 有 |
| 这台机器没有这个功能 | Windows 没有 NVIDIA 显卡时跳过补帧那一步。显卡是 RTX 20 及以上时才提 RTX 视频超分，RTX 40/50 才提 VFG。显卡型号从播放器诊断里的 CUDA 算力判断 |
| 服务器没开这个功能 | 一起看、消息、评论区不出现时，那一步自动跳过 |
| 目标看不见 | 比如手机窄屏把顶栏按钮收进了「⋯」。每步最多等 3 秒，换页时最多等 8 秒，没出现就跳过，总步数跟着减一（「6 / 13」） |
| 媒体库是空的 | 首页没有作品可打开，作品页那一章整章跳过 |

不管哪种情况，引导都不会卡在某一步。

## 五、操作方式

| 方式 | 操作 |
|---|---|
| 鼠标 | 点按钮。点暗处不关闭，防误触 |
| 键盘 | → 或 Enter 下一步，← 上一步，Esc 关闭，Tab 在气泡的按钮之间切换 |
| 触屏 | 点按钮；在气泡上左右滑动切换上一步和下一步 |
| Android 返回键、iPhone/iPad 左边缘右滑 | 关闭引导，底下的页面不会跟着后退。两边原生代码本来就先问网页 `tigerestClientMenuBack()`，引导接在这里，不用改原生代码 |
| 遥控器、手柄（桌面的电视布局，经 CEC 或手柄映射） | 左右切换步骤，确定键按下聚焦的按钮，返回键关闭。引导打开时，这些按键不再传给底下的 Emby 页面 |
| Apple TV 遥控器 | 左右切换，按触控板等于按聚焦的按钮，Menu/返回关闭 |

新用户的引导不能关闭，上表里「关闭」的按键在那里都改成退回上一步。

### Mac（最多 14 步）

和 Windows 相同，只有三处不同：

- 第 9 步的快捷键写成 ⌘, 和 ⌘O。
- 第 13 步改名「补帧」：在「设置 → 视频」里打开「AI 补帧（RIFE）」或「系统原生补帧」，把 24 帧的动画补到更高帧率。
- 不提 RTX 和 VFG。

### Android（最多 11 步）

1、3、4、6、7、8、10、14 和 Windows 相同，其余几步的差别：

| # | 和 Windows 的不同 |
|---|---|
| 2 媒体库 | 媒体库在顶部横排。说明改成「点一下预览，再点一下进入整个媒体库」 |
| 5 窗口与全屏 | 没有这一步 |
| 9 客户端菜单 | 说明改成「切换或管理服务器、播放器设置、客户端设置都在这里」，不提快捷键、离线媒体和本地视频 |
| 11 播放器 | 改成：第一次播放时会先教你手势——双击暂停，横着滑快进快退，左右两侧上下滑调亮度和音量，长按画面临时两倍速。其他设置在控制栏的「更多」里。 |
| 12、13 | 没有这两步 |

窄屏把「一起看」收进「⋯」时，顶栏的这一项本来就不讲（作品页的「一起看」按钮仍然讲）。手机上的气泡贴在屏幕下方，宽度占满，不挡住亮出的位置。

### iPhone / iPad（最多 12 步）

基本和 Android 相同，有两处不同：

- 第 9 步的说明加上「下载与离线媒体」，iOS 有离线下载。
- 第 11 步的手势按 iOS 播放器的「播放手势」说明来写，交 Mac 那边核对。

另外，如果这台设备支持补帧（`jmpInfo.capabilities.rife`，或 Apple 原生补帧），加一步「补帧」，说明它在「设置 → 视频」的哪里。

## 七、测试

- **测试开关：** 设置项 `main.onboardingTour` 等于 `off` 时永远不自动弹，重看入口照常能用。
  - 桌面的测试夹具 `tests/community_browser.cjs` 默认写入 `off`。所有 `*_webengine` CTest 和 `tests/*.cjs` 真实客户端脚本都经过它，所以都不会被挡住。
  - Android 夹具同样默认写入 `off`。
  - iOS 加启动参数（仿照现有的 `-TigerestPlaybackGesturesSeen YES`）。
  - Apple TV 在 `--tv-fixture` 下默认关闭。
- **引导本身的测试：** 新增 `tests/test_onboarding_tour_ui.cjs`，在真实客户端里跑，并注册成 CTest `test_onboarding_tour_webengine`。覆盖：
  - 新配置第一次进首页会弹出，走完后刷新不再出现；
  - 点 × 或「跳过」后不再出现；
  - 「重新打开引导」能重新开始；
  - 缺少目标时跳过并重算总步数；
  - 键盘、返回键、遥控器的按键能用；
  - 平台不同时步数不同；
  - 浅色主题下气泡换成白底；
  - 进度写进设置。
- **真实客户端走查：**
  - Windows 用隔离配置，连真实服务器走一遍全部步骤，每一步截图；
  - Android 在测试手机上覆盖安装调试版（保留登录），走一遍并截图。

## 八、分工（已选 A）

- **这台电脑：** 共用引导脚本、Windows（Mac 的 Qt 版和 Windows 是同一份代码）和 Android 的实现与测试。
- **交接说明：** iPhone/iPad 需要的几处小改（把新脚本加进同步清单、`SettingsStore.swift` 白名单和新旧用户判断、测试启动参数、核对手势文案），以及 Apple TV 的原生引导。
- **Mac 那边：** 实现、编译、测试 iPhone/iPad 和 Apple TV，并在 Mac 上编译 Qt 版，跑测试、走一遍引导。
