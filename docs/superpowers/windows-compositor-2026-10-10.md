# 2.5.3 Windows 海报墙花屏排查记录

用户最终将场景收敛为媒体夹海报墙悬停，首页基本没有发现。当前仍按未解决问题记录。

## 版本核对

已安装 EXE 与 2.5.3 发布便携包完全一致，SHA256 为 `979007f65e8b8045589c496ea76bb654cb6ee60f4c15a8de80bd1925a4afe410`。
实际 QtWebEngine 核心 DLL SHA256 为 `9d410e8aa09e04dcafe759dd4446895011976ad4577e7d7b1977ee8cc156902b`。
旧 D3D11 producer 同步补丁在包内，启动日志显示 `completed=1, reset=0`。这只能证明补丁已执行，不能证明 Qt 最终显示的所有画面正确。

## 本次验证及边界

- 在隔离本地海报墙中运行完整 2.5.3 客户端，使用生产外观样式和转场预缓存。
- 独立工具通过 GDI 采集桌面上真实客户端像素，未向应用插入 GPU 等待或使用 CDP 截图替代显示结果。
- 最终便携包复测在窗口、滚动后、全屏共采集 372 帧、实际收到 8383 次 pointermove，固定海报中心检查区未损坏。发出事件数量不等于实际收到数量，因此单独计数。
- 一次全屏检查捕获了 NVIDIA 提示浮窗。保留失败证据并检查截图后，等待浮窗消失再复测；该失败不是应用花屏证据。
- 负对照故意给可见海报设置错误预期颜色，采集器明确失败。单元检查还验证了单像素缺块、空图、越界和无样本均被拒绝。
- 修正 CTest 取证：从被测 PID 的模块列表获取实际加载的 DLL 路径，不能假定 DLL 总在 EXE 旁。
- 原生窗口测试与发布包测试采用独立配置；未修改已安装客户端及用户配置。

固定中心取样不覆盖全部像素；CDP 注入输入也不等于物理高回报率鼠标经过 Qt 的完整事件链路。本次没有稳定捕获用户描述的海报墙故障，没有进行真实媒体库或真实播放返回的人工验证，不能声称花屏已修复。

完整 CTest 78 个目标通过（331.95 秒）。其中 5 个 Qt 用例按原有条件跳过：3 个需要独占桌面的光标集成用例、当前显示器工作区不满足条件的无边框最大化用例，以及需要私有运行库的真实 RIFE probe 用例；不能把它们计为实际播放或桌面交互验证。两份工作流 YAML 语法检查通过，云端新工作流尚未运行。独立审查发现的附件下载顺序和旧报告残留问题已修正，相关负对照回归通过。

## 后续更新必检

详见 `dev/windows/RELEASE_CHECKLIST.md`。构建程序与最终便携包均检查实际窗口像素，失败帧作为 CI 附件保存。每次运行先作废旧报告，失败重跑不能沿用旧的通过结果或人工审批。

发布还须提交正常刷新率、正常鼠标回报率下的真实媒体库人工记录，覆盖悬停、滚动、详情返回、播放返回、全屏和设置浮层。校验器拒绝软件设备、失败/缺失检查、人工未完成，以及与最终包 EXE/核心 DLL 哈希不同的证据。当前 `manual.passed=false`，已知复现仍未解决，不能签发新 Windows 发布通过。
